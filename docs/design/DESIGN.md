# design.md: Bistre Sepia Book UI Design System

Single source of truth for Bistre's visual tokens, typography, spacing, 10 Ink Primitives, layout modes, motion language, and accessibility invariants. All Flutter UI code in `apps/bistre_app` must derive from this document (`ADR-0001`, `ADR-0011`).

## 1. Visual Identity, Plain Copy & Anti-Slop Discipline
- Metaphor: Illuminated archival book and brass fountain nib on warm paper (`assets/brand/bistre-icon.svg`): visual craft only, never user-facing copy jargon.
- App icon: one icon everywhere, the book and nib with no background plate (`assets/brand/bistre-icon.svg`). The Android adaptive launcher icon (transparent background layer; foreground `ic_launcher_foreground.png` on a 108 dp canvas with the icon in the central 66 dp), the Windows `app_icon.ico` (16, 20, 24, 32, 40, 48, 64, 128, 256 px), the Linux `bistre.svg` and 256 px `bistre.png`, and the sidebar mark (`apps/bistre_app/assets/icons/bistre_icon.vec`) all come from it. Regenerate the `.vec` with `dart run vector_graphics_compiler -i <svg> -o <vec>`; render the icon from vector at 1,024 px, resample each PNG size from that with premultiplied alpha, and pack the Windows sizes as ICO entries.
- Plain Everyday UI Copy (Mandatory): Every label, button, tab, placeholder, and empty state must use normal everyday words a competent non-expert understands (`Send`, `New chat`, `Recent`, `Pinned`, `You`, `Light`, `Dark`, `Document`, `Bubbles`, `Settings`, `Providers & Keys`, `API key`, `Daily spending limit`). Never expose internal or literary jargon in user-facing strings across any locale (`en`, `vi`, `ar`; enforced by `just i18n-check`).
- Vertical-First Restraint: Use clean vertical list items for navigation, providers, assistants, topics, chats, and settings rows. Only place controls horizontally where 2–3 compact options naturally fit on a single row.
- Focal Point: One primary reading/writing surface per screen. No decorative card grids, no gratuitous gradients, no drop-shadow soup, no emojis as UI icons.
- Surface Separation: Subtle translucent hairline borders (1px) and stepped warm tonal layers (`bgCanvas` → `bgSurface` → `bgElevated`).

### 1.1 Craft Principles
- Bubbles hold only the message: model icon, name, timestamp, and the collapsible `Thinking` summary sit outside the bubble; code cards carry only language + line count and trailing icon buttons.
- One bold mark: a single `rubricMark` start-edge accent bar (`apps/bistre_app/lib/design/bistre_decorations.dart`) marks only the selected sidebar chat, the active settings category, the empty-chat intro, and user prompts in `Document` layout: never competing accent borders.
- Controls appear when needed: desktop row/message actions reveal on hover or keyboard focus (plus right-click menu); on touch, the newest turns show their actions, a tap on an older message shows or hides its actions, and the open chat's sidebar row shows Pin, Rename, and Delete; Android long-press stays reserved for native text selection. A hidden action never takes a tap.
- Explain on hover: every icon button and chip shows a short plain hint of what happens.
- Undo instead of asking: deleting a chat shows an 8 s `Undo` toast instead of a confirmation dialog (an opt-in Appearance setting turns the delete into a second click on the same button, never a dialog); bulk destructive actions (`Clear all`) never sit next to routine sidebar or filter headers: they live in Settings → Storage. Erasing everything on the device has no undo, so it takes a second press on the same button and waits for the next start, with Keep my data until then.
- Empty states teach the next step: the empty chat shows a `rubricMark` intro ("Start with a question, a draft, or a file."), the active model, and one `Set up <provider>` button when no key exists; an empty model list explains why and offers `Fetch models`.
- Single top header bar: at most one ~60 dp header (sidebar toggle, chat title, interactive model subtitle; workspace + settings on the trailing edge): never stacked double bars. The native window caption reads `<chat title> - Bistre` (or `Settings - Bistre`) with live run progress; off-screen window bounds recenter on launch.
- Typed icons only: pass `BistreUiIcon` enums directly; never encode icons as emoji strings or parse labels back into icons.

### 1.2 UX Craft Principles (universal)
These apply to every surface, now and later. They name no screen or control on purpose: test any design against them, and when one conflicts with a specific rule elsewhere in this document, raise it with the maintainer rather than quietly picking one.
1. Show, don't tell: let geometry, iconography, grouping by proximity, contrast, and live state explain what a control does before any text does. A label is the last resort, not the first.
2. Zero tautology copy: no subtitle, caption, or helper line may restate a control's own label or current value. Secondary text earns its space only when it explains a non-obvious consequence, a privacy or cost trade-off, a scope limit, or a way to recover. If deleting it loses no information, delete it.
3. Uncluttered action surfaces: an everyday action is one clear icon or one crisp verb, never a stack of word + icon + shortcut badge on the same face. Shortcuts and longer explanations live in hover hints and accessibility semantics.
4. State lives on the control: active, inactive, disabled, loading, progress, unsaved, and error show on the affected control itself, through shape, contrast, inline values, and restrained motion, not through an extra sentence or a banner elsewhere.
5. Spatial stability and rhythm: controls keep their place across state changes, panel toggles, hover reveals, and streaming. No coordinate jumps, frame-by-frame reflow, empty gaps left by hidden controls, doubled chrome (two bars, two borders, two close buttons for one thing), or competing accents.
6. Progressive disclosure and hierarchy: the reading and writing surfaces stay calm. Related controls group by proximity, the primary action carries the clear focal weight, and secondary options, rare destructive actions, and technical diagnostics sit behind a disclosure or in a secondary panel.
7. Forgiving everyday ergonomics: prefer reversible actions with undo over interrupting dialogs; keep the user's work across focus, view, and resize changes; prevent accidental triggers (no invisible hit targets, no focus theft, no surprise sends or cancels); every error says what to do next and appears only where it happened.
8. Real-world stress resilience: every layout stays legible, balanced, and usable with messy real input: very long unbroken strings, mixed scripts and diacritics, dense code, tables, and math, narrow split windows, touch, 200% text, RTL mirroring, and every light and dark preset. Measure real widths instead of guessing from a text-scale threshold; translated labels differ in length.

Review checklist (every UI change and every gallery review, at phone, desktop, 200%, RTL, light and dark): Is any text restating something the eye already sees? Does any control show its state only somewhere else? Does anything move, gap, or wrap when state changes? Is there exactly one focal action? Does the longest real string, in the longest locale, still fit or degrade gracefully? Is every destructive or rare action out of the everyday path and undoable?

## 3. Offline Bundled & Local Custom Typography
Bundled static OFL weights serve as zero-network defaults (zero runtime font fetches):
- Prose & UI: `Inter` (`Regular` 400, `Medium` 500, `SemiBold` 600, `Bold` 700)
- Code & Diffs: `JetBrainsMono` (`Regular` 400, `Medium` 500)
- Math: `NotoSansMath` (`Regular` 400), registered lazily on the first rendered math block
- Budget: all bundled font files together ≤ 2.0 MB (currently 1.58 MB), OFL-subsetted with fontTools `subset` to Basic Latin, Latin-1, Latin Extended-A/B, Latin Extended Additional (full Vietnamese), combining marks, Greek, punctuation, currency, letterlike, arrows, math operators, technical, box drawing, shapes, and dingbats; `NotoSansMath` additionally keeps math alphanumerics and supplemental operators. Arabic renders through the platform fallback font. None of the three fonts declares a Reserved Font Name, so subsets keep their names (`docs/specs/11-performance-and-budgets.md`).
- End-User Typography Control: Users can pick any locally installed OS font or browse a local `.ttf`/`.otf` file (`apps/bistre_app/lib/platform/font_manager.dart` via `FontLoader`), and continuously adjust base font size (`12–28px`), line height (`1.30–2.00`), reading column width (`600–1120px`), theme (`System | Light | Dark`), and accent presets or custom `#RRGGBB` hex (with automatic WCAG AA contrast selection via `BistreAccentOption.highContrastInkOn`).

## 3.5 Offline Vector Iconography
- Custom Editorial UI Icons: Hand-crafted 24×24 pixel-aligned SVG icons pre-compiled offline to `.vec` under `apps/bistre_app/assets/icons/ui/` (`BistreUiIcon` / `BistreIcon` / `BistreIconButton` in `apps/bistre_app/lib/design/bistre_icons.dart`). Strokes are 1.75 wide with round caps and joins. Strokes that cross go in separate `<path>` elements: the compiler cancels where one path overlaps itself, which shows as white notches. Sources kept in the repo (`assets/icons/*.svg`) compile with `dart run vector_graphics_compiler -i <svg> -o <vec>`.
- Offline AI Lab Icons: Pre-compiled `.vec` provider marks under `apps/bistre_app/assets/icons/labs/` (`LabIconCatalog` / `LabIcon`), supporting optional local user PNG/WebP custom provider images. Zero external icon catalog references or network URLs exist in runtime code (enforced by `just guard`; all third-party attributions live strictly in [`third-party-notices.md`](../../third-party-notices.md)).

## 4. 8pt Spacing, Radii & Layout Modes
- Spacing Scale: 4, 8, 12, 16, 24, 32, 48 logical px (strictly `EdgeInsetsDirectional` for RTL).
- Radii: 6 (chips/inputs), 10 (surfaces/bubbles), 14 (composer/modals), 999 (status pills).
- Reading Measure: prose width 760px by default (user range `600–1120px`, see §3), centered, for chat prose only; full-width breakouts expand wide tables, diffs, and code blocks up to 1160px on desktop. Settings and other tool pages fill the content width (24–28 px gutters) so wide windows show more content rather than empty margins.
- Dual Layout Modes:
  - Bubbles: User utterances aligned `AlignmentDirectional.centerEnd` in warm `bgSurface` cards; assistant responses aligned `AlignmentDirectional.centerStart` with hairline ink border.
  - Document: Full editorial column where user and assistant turns alternate with engraved hairline rules, speaker rubric labels, and generous typographic breathing room.

## 5. Disciplined 10 Ink Primitives Budget
Every screen in `apps/bistre_app` composes exclusively from these 10 reusable widgets in `apps/bistre_app/lib/design/ink_primitives.dart` (mechanically verified by `just guard`):
1. `BistreScaffold`: Edge-to-edge viewport inset scope (`paddingOf` + `viewInsetsOf`), top bar, scrollable body, docked composer slot.
2. `FolioSurface`: Tonal container (`canvas`/`surface`/`elevated`) with optional 1px hairline border.
3. `InkText`: Semantic text primitive binding `BistreTypography` & `BistreThemeData` colors.
4. `EngravedButton`: Keyboard-focusable (`FocusableActionDetector`), visible brass focus ring, hover/press opacity shift, `Semantics(button: true)`.
5. `WaxSealBadge`: Status seal pairing icon glyph + localized label + tonal border (never color alone).
6. `QuillInput`: Pure `EditableText` wrapper with IME composing guard (`!value.composing.isValid`), Shift+Enter newline / Enter submit, focus ring, placeholder overlay.
7. `FolioDivider`: 1px horizontal/vertical `borderHairline` rule.
8. `InkChip`: Compact toggleable chip (layout, theme, locale, mode) with explicit selected state semantics.
9. `FolioOverlay`: `OverlayPortal`-backed modal/popover with Escape dismiss and focus trap.
10. `EngravedIcon`: Unified `.vec` (`vector_graphics`) resolution-independent GPU `ui.Picture` renderer (`vg.loadPicture` + `CustomPaint`, zero low-res raster downsampling/bilinear blur, zero Material Icons, zero emojis).

## 6. Motion: Instant Where You Act, Alive Where You Look
Animation never delays an action: the action fires on the event, and motion only describes it.
- Instant (0 ms): typing, sending, every keyboard-initiated action, thread switching, and message arrival. A committed message never replays an entrance animation.
- Timings: `BistreMotion.arriving` 150 ms, `leaving` 110 ms, `travelling` 180 ms, `Curves.easeOutCubic`.
- Pointer feedback on every clickable (buttons, chips, icon buttons, rows, tabs, header pressables), built into the shared primitives so every screen gets it:
  - press scales to 0.96 (spring damping 0.78, stiffness 680);
  - hover scales to 1.012 and lifts 0.75 dp (spring, no bounce, stiffness 560);
  - wide rows (sidebar chats, list rows, tabs) press to 0.985 and only lift on hover, so a 300 px row never visibly jumps (`kRowPressScale`);
  - the focus ring shows for keyboard focus only, never after a pointer press.
- Disclosures & docked panels animate smoothly:
  - Disclosures (`DisclosureReveal`, stiffness 420) ease height + fade on a critically damped spring;
  - The docked desktop sidebar (`SidebarDock`, `apps/bistre_app/lib/design/sidebar_slide_reveal.dart`) slides over `travelling` with `Curves.easeOutCubic` and reverses from where it is mid-flight. The chat area takes its final width once, when the toggle is pressed, and only moves while the sidebar slides, so text, titles, and the composer never re-lay out frame by frame. No fade (no offscreen layer per frame). A closed sidebar stays mounted (offstage, not ticking, not focusable) so reopening it costs nothing. The trailing docks (inspector, Studio) are the same `SidebarDock` at the trailing edge, so the chat also takes its final width once when one opens, and they stay mounted while closed;
  - The header has one sidebar toggle, always first in the chat header (open or closed, LTR or RTL), and the trailing header buttons (New chat, Studio, Settings) are always there and never change with the sidebar; the phone drawer keeps its own close button;
  - `BistreSlider` thumbs glide smoothly on tap/step via critically damped spring (stiffness 520) and track 1:1 on pointer drag; in RTL the minimum sits at the right edge and the thumb stays on the track;
  - Settings category changes cross-fade smoothly via `FolioFadeSlide`.
- Overlays, banners, and pills:
  - modals, menus, and popovers fade and rise in over `arriving`, and leave over `leaving`.
  - Slim top update/status banners (`FolioTopBanner`) reveal beneath the header via `DisclosureReveal`.
  - Floating pills (centered top toasts `• <message> [Action] ×`, Jump to latest) pop in from half their height, scale 0.90 to 1 and fade, on a brisk spring (stiffness 580).
  - Side drawers slide over `travelling`.
- State changes: selection, toggle, chip, and accent colours cross-fade over `travelling` (`EaseDecoration` in the button, chip, icon-button, and switch primitives); progress and token counters ease to their new value.
- Scrolling:
  - on desktop, mouse-wheel scrolling is smooth: notches accumulate into a target that the view eases toward (170 ms ease-out, `SmoothScrollController` in `apps/bistre_app/lib/design/smooth_scroll.dart`; scroll views without their own state use `SmoothScrollable`);
  - trackpad and touch scrolling stay 1:1 (pan-zoom gestures and wheel deltas of 16 px or less pass straight through), and Reduce motion keeps the plain jump;
  - programmatic scrolls (Jump to latest, search hits, branch switches) glide over `travelling`.
- Streaming text is paced: replies and thinking reveal in step with the display frame clock:
  - ~92 characters per second, carrying fractional characters between frames;
  - elastic catch-up when more than 28 characters are waiting (the excess shrinks on an 80 ms time constant);
  - the rest appears at once when the reply is committed.
  Implemented in `LiveTurnNotifier` (frame callbacks only while text is waiting, so zero idle frames); Reduce motion and low-memory mode publish each batch as it arrives.
- App text size: Settings → Appearance offers 90, 100, 115, and 130% of the system text size for every screen (applied at the root `MediaQuery`, so layouts react exactly as they do to the system setting); the reading font size is a separate setting for message text.
- Reduced motion: if `MediaQuery.maybeReduceMotionOf(context)`, `maybeDisableAnimationsOf`, `maybeAccessibleNavigationOf`, or the user's `reduceMotionOverride` is true, every duration and spring above resolves to an instant change, including ones already running, and streamed text appears as it arrives. The streaming cursor stops breathing the moment it turns on. Sideways entrances start from the reading end, so they mirror in RTL. A reveal never ends on half an emoji.

## 7. Accessibility, IME & RTL Non-Negotiables
- All interactive controls are keyboard-focusable (`FocusableActionDetector`; never a bare `GestureDetector`) and expose `Semantics` labels, keyboard-only 2px `accentBrass` focus rings (shown when focus arrived by keyboard, never after a pointer click), and minimum `40x40` touch/click targets (`48x48` on Android). Small icon buttons keep their visual size and take taps across the full target through `TapTargetExpander` (`apps/bistre_app/lib/design/bistre_icons.dart`); where two targets overlap in one row, the button whose own box holds the tap, else the nearer one, takes it. Custom tappable content (a pinned reply, a waiting attachment) uses `PressableArea` (`press_feedback.dart`): a labelled button that Enter and Space also press. Text cut to a length (titles, quotes, previews, file names) is cut by visible characters, never through an emoji (`clipText`, `apps/bistre_app/lib/features/chat/plain_preview.dart`). Disabled buttons keep their hairline outline.
- 200% text scale: fixed-width columns (sidebar, settings nav) scale with `textScaledWidth` up to 1.6x; the composer toolbar measures its controls' real widths and uses the first form that fits in one row (full labels, then the context ring without its number, then icon-only Tools and Live, then the short Thinking label), splitting into two rows only when none fits; below 720 px the composer is always one row (see §10, Composer); icons grow with the text size up to 1.5x (`iconScaleOf`, `kMaxIconScale` in `bistre_decorations.dart`), and a reply's action buttons wrap or drop below its name when they do not fit beside it; when the effective width (width ÷ text scale) is below 600 px the header stacks (and wraps) secondary actions at ≥ 135% text; a setting row keeps its control (switch, compact picker, short button) beside the label whenever both fit and drops it below only when it does not (`LabelControlLayout`, `apps/bistre_app/lib/design/label_control_layout.dart`, measures the real widths; no width threshold); popovers are capped to the window less a 12 px margin and shifted back inside it (`PopoverPlacement`); below 720 px Settings switches to the compact phone layout (`apps/bistre_app/lib/features/settings/settings_mobile.dart`): one header (`Settings` + `Chat` at the root, a `Settings` back button + page name on a page), a search field, and a vertical list of page cards (tinted icon box, name, one-line summary, matched settings, chevron); one page at a time; Android back and a start-edge swipe (72 px) step back from search, to the page, to the list, then close; at ≥ 130% text the page name gets its own header row; every model/provider/assistant pill uses `Flexible` + ellipsis. The UI gallery renders `phone-text200` and `desktop-text200`.
- Modals and drawers trap focus (`FocusScope`) and wrap occluded background UI in `ExcludeSemantics` + `ExcludeFocus`; every input keeps its accessible field name; toasts and errors are `liveRegion`s.
- All directional spacing/alignment uses `EdgeInsetsDirectional`, `AlignmentDirectional`, and `TextDirection` resolved from active `BistreLocalizations`.
- Message direction follows the message: chat content takes its direction from its first strong character (`contentDirection`, `apps/bistre_app/lib/features/chat/content_direction.dart`), so an English reply inside the Arabic UI reads left to right with its punctuation in place, and an Arabic reply inside the English UI reads right to left; text with no strong character keeps the UI direction.
- Never alter `TextEditingController.text` during active IME composition (`value.composing.isValid`); an edit that has to wait (clearing sent text, restoring a draft) runs as soon as the composition ends. While composing, arrows, Tab, and Enter belong to the IME (the `/` and `@` menu and the command palette ignore them). Never set `enableSuggestions: false` on general text inputs (`flutter#192714`).
- Text fields (`QuillInput`): a one-line field always submits on Enter (`TextInputAction.done`); in the composer Enter sends unless Settings → Appearance → Enter sends the message is off, and Ctrl+Enter (Cmd+Enter) always sends; the field itself carries its accessible name (the placeholder unless `semanticsLabel` is given) and the drawn placeholder is hidden from screen readers. The right-click menu uses Flutter's live rules (`TextSelectionHandleControls`): Paste only when the clipboard holds text, no Cut or Copy in a masked field; selected message text gets Copy and Select all. Only messages are selectable; the empty chat page is not. Copied text keeps a line break between paragraphs, list items, and code rows (`LineSelection`).
- Close buttons are named for what they do: Dismiss for a notice (toast, banner, error), Close for a panel, dialog, or search bar, Remove for an attached file or queued message; Cancel only cancels an action. A disabled button tints its icon with the muted ink, so it never looks empty.
- Model field (`ModelPickerField`): one combobox, no second filter box or Choose button; the list opens under the field, follows the highlight with arrow keys, and closes on Enter, Esc, or a click elsewhere.
- Renaming a chat: click the header title; Enter or clicking elsewhere saves, Esc cancels (and never reaches the reply). The box fits the title (up to 420 px) and closes when the chat changes or Settings opens.
- Esc and stopping a reply: Esc stops a reply only from the empty composer (not mid-IME, no menu open); from any other field it only closes that field's layer. `Ctrl+.` (rebindable, Shortcuts) and the Stop button stop it from anywhere. Custom shortcuts (Settings → Shortcuts, `shortcut_combo.dart`): one parser records and binds them; F1–F12 work alone, a letter or digit needs Ctrl, Alt, or Meta (so it never stops typing), Ctrl+A/C/V/X/Y/Z stay for editing, and a shortcut another action uses is refused with that action's name while recording goes on. A scroll that moves up during a reply stops auto-follow, which resumes only when a scroll ends near the bottom or on Jump to latest.
- Modals (`FolioModalBackdrop`): Tab cycles inside the modal, the page behind it is excluded from focus and semantics, and focus returns to where it was when the modal closes.

## 8. Hot-Path UI, Viewport & Low-Memory Invariants
- Leaf-isolated state: 16 ms streaming deltas flow into a dedicated leaf `ValueNotifier` (`LiveTurnNotifier`) read only by the active streaming turn inside a `RepaintBoundary`; the shell, header, and sidebar rebuild 0 times per delta. The composer owns its `TextEditingController` (keystrokes never notify the root). Hover, press, focus, and pulse layers animate inside leaf `RepaintBoundary` widgets with 0 parent rebuilds.
- Viewport & scroll: the message feed is a full-width `CustomScrollView` (`SliverList.builder`) whose items each center a `ConstrainedBox(maxWidth: readingWidth)`, so the mouse wheel scrolls from the empty page margins; a non-empty chat opens anchored at the bottom; auto-follow pauses immediately on drag or wheel.
- Code & tools: code fences soft-wrap by default on a phone width (Spec 08 Code Fences), with a global `Wrap code` preference and a per-fence wrap toggle that survives scrolling; fenced `svg` blocks offer an offline `Preview` / `Source` toggle; wide layouts (≥ 720 px effective width) offer a `Split` / `Unified` diff toggle; consecutive read/search tool steps fold into one quiet row; Markdown export skips empty assistant stubs.
- Composer context gauge: a compact radial `ContextGaugeRing` (`apps/bistre_app/lib/features/chat/context_gauge_ring.dart`) shows how full the conversation limit is. Every number comes from core (`context_breakdown`, `crates/bistre-core/src/context_breakdown.rs`), counted with the builders a run uses, so it never counts text the model will not see. Tapping it opens What fills this conversation (`context_breakdown_popover.dart`): the share used in the header, one stacked bar, then a row per category with tokens and its percent of the limit (Messages with turn count, Built-in tools, MCP tools, Instructions, Project instructions, Workspace instructions, Story notes and cards, Attachments, Unsent draft; empty rows hidden), Kept free for shortening, Free space, and below a divider what is not sent (MCP tools on demand, "-" for the percent). The MCP row opens a second page listing each server's tools with their schema size; Esc goes back a page, then closes; the page switch cross-fades and honours Reduce motion. Each row is one labelled screen-reader node. When the full toolbar does not fit in one row, the ring drops its number label first, then Tools and Live become icons, then the Thinking and Format chips show only their values (`Auto`, `16:9 · 2K`): they name the choice, so they shorten last, keeping the full names for screen readers and hover hints (§7).
- Summary card: the summary of shortened messages keeps its actions (Edit, Undo shortening; Cancel, Save while editing) on one wrapping row at the card's end, so long labels and 200 % text wrap instead of overflowing; actions hide while a reply is being written.
- Low-memory mode: Spec 11 (no overlay drop shadows, a lower redraw rate, smaller decodes and GPU cache).

## 9. Recovery Surfaces & Plain-Language Glossary
- Backoff notices show the countdown, the plain reason, and an inline trailing `Retry now` button; fixable errors (bad key, missing model, conversation limit, spending limit) show one button that jumps straight to the fix, beside the sentence or below it when both do not fit. A reply a restart cut off shows the same notice with `Try again`. Unavailable costs show a quiet info icon with a breakdown popup instead of noisy "cost unavailable" text.

## 10. Screen Anatomy
- Header (one bar): leading sidebar toggle → chat title (click to rename) with `model on Provider ▾` as an interactive subtitle beneath it → trailing New chat, Studio, and Settings, always present and never changing with the sidebar or the inspector and Studio panes, which dock below the header (§6). Chat titles in the header, sidebar, and tabs follow their own text direction (`OwnDirection`). Slim update/status banners reveal directly below the header when needed; centered top floating pill toasts announce connection checks, copy, pin, and undo notices. On wide windows, open chats show as a slim tab strip under the header only once two or more are open (it is part of the header, not a second bar). Every icon has a hover hint.
- Message: messenger bubbles by default: yours a tinted pill on the trailing side; replies a hairline-bordered card. Model name and time sit above the bubble, with a collapsed `Thinking` toggle on the trailing edge and collapsible Agent Step Checklists (`Worked for Xs · N/N steps`). Actions reveal on hover or keyboard focus (`Copy`, `Regenerate`/`Edit`, and expandable inline `More` for reply/pin/context start/turn details/delete); a trailing `MessageNavRail` with `Message Map (N/N)` supports fast long-thread navigation. In bubbles the speaker, model, and actions sit above the bubble, which holds only the message (§1.1). Each reply ends with one usage line, `↑sent ↓received cost` (screen readers hear it in words); hovering it on desktop for 500 ms, or tapping it, opens the breakdown (sent, reused and saved cache, thinking, received, time to first word, total time, speed, exact cost), which Turn details also shows first, above its folded raw metadata. A reply that used web pages shows a globe with their count that opens them. Sent files show a type icon, the name shortened in the middle so the extension stays, and the size. Tool rows carry each tool's own icon and a status dot; only waiting and failed rows add a word. A checklist interleaves each step's thinking with its tools in the order they ran; the live reply shows only the step in progress, open, and folds it into the checklist once committed.
- Code card: `language (N lines)` on the leading edge; optional SVG `Preview`/`Source` toggle plus wrap, fold, download, and copy as equal icon buttons on the trailing edge.
- Composer: the only elevated surface on the page; placeholder `Message <assistant>...`. Bottom row: Attach, Add folder (a folder icon, lit while the chat can read a folder; each pick adds one more workspace folder; in a project chat with its own folder it, `@mount`, and the Tools popover's Choose folder open that project's settings instead, since the chat works only there; `composer_folder_button.dart`), `Tools` popover (Mode `Chat/Plan/Build/Write`, 4 Tool permission presets `Off/Strict/Balanced/Sandbox`, native OS `Choose folder...`, Web search, reply prefill), `Thinking` level (one `ThinkingEffortPicker` everywhere it appears, composer, inspector, and provider settings: `Auto` and `Adaptive` chips, then a slider over Off–Max that shows a hollow thumb and no fill while Auto or Adaptive is chosen), `Draft saved`, the labelled conversation-limit ring, and a quiet `Send` on the trailing side. Below 720 px the composer is one row: `+` (opens a tray with Attach, Add folder, Tools, Thinking, Live, and Send now while a reply runs; a dot on `+` marks a Thinking level other than Auto), the context ring, the field, and one action that is the mic when the field is empty, Send when it has text, and Stop (plus Queue once there is text) while a reply runs. A notice above the composer pushes the chat up and a reader at the bottom stays at the bottom, so the last usage line is never hidden. The `/` and `@` menu has no count; a row cut at its edge fades (`ScrollEdgeFade`). The context ring and its popover round shares the same way (whole percent, <1% for a non-empty share, never 100% unless full), and the ring is full and red while the provider reports the chat over its limit. Typing `@` or `/` opens a vertical keyboard-navigable menu with live mounted files, `@mount`, slash commands, and installed skills; while it is open, Enter picks the highlighted entry (it never sends `/plan` as a message). Text typed while a reply streams is never cleared. The draft follows the text: after Send or a command the saved draft is empty, and the last keystrokes are saved when the app is backgrounded or closed.
- Empty chat: one `rubricMark` line, "Start with a question, a draft, or a file." (the header already names the model). Without a key, one clean setup card with a single `Set up provider` button (zero hardcoded brand icon strip).
- Sidebar: search field with a `+` new-chat button, then `Assistant | Chat | Pinned` (showing both pinned chats and pinned replies); the Chat list opens with a `Projects` caption and its `+`, each project as a row (chevron, folder, name; `+` New chat in it and its settings) with its chats indented one step toward the reading end, then the other chats grouped by date, each row a title and relative time, with the assistant's name only when it is not the default one. Only the selected row carries the `rubricMark` (open tabs, palette rows, and provider rows show selection by tint); row actions reveal on hover or focus. An active filter shows its words in the search field with a clear button. `Delete all chats` lives in Settings → Storage (first click asks, second deletes), never in the sidebar.

### 10.1 Interaction Patterns
- Model picker: cross-provider searchable picker (`ModelPickerPopover`): search input (`Enter` selects top match), provider filter chips (`All providers`, then each provider's name, no counts), model-family filter chips (`All families`), active model pinned first when unfiltered, and badges only for exceptions: `On device` in ok ink for loopback hosts, `Stored` when the provider keeps replies, and the provider's name only when its icon cannot show it.
- Tab switcher: desktop tab strip (`ChatTabStrip`) adds `+` and an overview icon button whose hint and label name the count (`N tabs`), never a count printed beside the visible tabs, and phone headers show a compact tab counter badge once > 1 tab is open or any background chat is streaming; both open `TabSwitcherModal` (bottom sheet on phone, centered modal on desktop, 1 column below 420 effective px, filter above 3 tabs, `Close N empty`, `StreamingPulseDot` on streaming tabs). `Ctrl+Tab` / `Ctrl+Shift+Tab` cycles open tabs.
- Android back: back closes the innermost open layer first (command palette, overlays, tab switcher, chat map, model picker, studio pane, inspector, search panel, phone drawer); Settings steps back inside itself; with nothing open the app exits as usual.
- Context menu: right-clicking a sidebar chat offers Pin, Rename, and Delete; right-clicking a message opens its actions at the pointer (Reply or Edit, Copy, Pin reply, Turn details, Regenerate, Start context here, Delete in error ink); right-clicking a code card offers Copy, Wrap/Unwrap, Fold/Unfold, and Save (`ContextMenuRegion`, `apps/bistre_app/lib/design/context_menu.dart`). Arrow keys move, Enter chooses, Escape or an outside click closes. Rows are full tap targets and grow with the text; the menu is measured and kept inside the window. Touch keeps the visible action bar, because long-press selects text.
- Hover hints: icon buttons, header pressables, context gauge, thinking chip, and per-turn usage pills name themselves in a small bubble 500 ms after the pointer rests on them (`HoverHint`, `apps/bistre_app/lib/design/hover_hint.dart`), placed below or above near the bottom edge, and gone on exit or press. Pointer only.
- Settings copy: a row label never repeats its button, its value, or its section heading; a field's label names it and its placeholder gives an example; a slider's value shows once at the row's end with Reset beside it when changed; permissions name tools in words (`Read files`, `Run commands`); schedules read as words (`Every day at 09:00 UTC`, `Every 15 minutes`) with the last run's outcome; the Studio run card names its chat, mode, and step in words and its status as a calm seal (`Running` is not a warning); the prompt inspector names each part and each lore reason in words and marks the cache boundary with a quiet divider; the write-mode bar is a `Chat | Manuscript` switch, two action buttons, one options button (dialogue highlight and samplers), and the cast in plain text.
