# Spec 02 — Providers, Wire Protocols & 5-Class Self-Healing Engine

## 1. Zero Third-Party LLM SDKs & Pure-Rust TLS Transport
All provider adapters run in `crates/bistre-core` (`crates/bistre-core/src/providers.rs`) on `reqwest 0.13` + `rustls 0.23` (`ring` crypto provider) + `rustls-platform-verifier 0.7.1` (honoring OS/enterprise CA trust stores and system proxies; `openssl-sys` and `aws-lc-sys` banned via `deny.toml`).
- API keys are retrieved strictly from the node-local encrypted OS `SecretVault` (`LocalSecretVault` in `crates/bistre-crypto`, using Windows DPAPI `CryptProtectData`/`CryptUnprotectData` with in-place zeroization on drop). When no provider is configured, Bistre returns `DiagnosticKey::ProviderNotConfigured` and NEVER fabricates fake mock AI replies.
- Live `/models` discovery fetches model lists on demand from each provider's API (zero hardcoded model tables per Spec 03) alongside manual model ID entry.
- **Live Generation Parameters & SSE Usage Accounting**: `GenerationParams` (`temperature`, `max_output_tokens`/`max_tokens`, `top_p`) resolved via `Thread override → Assistant default → provider default` are forwarded natively across OpenAI Responses, Gemini, Anthropic Messages, and OpenAI-Compatible streams (`stream_options: { include_usage: true }`). Real input/output token counts are extracted from SSE payloads, persisted onto `nodes.provider_meta_json`, and converted into exact integer `MoneyMicros` entries in `wallet_ledger` (`$0.00` automatically for loopback local servers).
- **`SseFramer` (`crates/bistre-core/src/sse.rs`)**: UTF-8 carry-over across chunks; BOM stripped at stream start only; single-line complete-JSON `data:` frames dispatched immediately (no wait for the blank separator); `\r\n` / `\n` / lone `\r` endings with a held-back trailing `\r`; plain-JSON body fallback when the upstream ignores `stream: true`; hard `64 MiB` buffer cap. Each byte is searched for a line ending once (a `scanned` cursor), so a long line split over many chunks costs linear time (16 MiB in 16 KiB chunks: 317 s before, under 1 s after; test `a_long_line_in_many_chunks_is_scanned_in_linear_time`). A cap hit follows the dropped-stream rule (R8): retried only when nothing was shown, otherwise the output is kept and the reply marked interrupted (test `a_buffer_cap_after_output_marks_the_reply_interrupted_instead_of_retrying`). `StreamingTextBuffer` normalizes split `\r` + `\n` in text deltas before they reach the UI.
- Captive portal guard rejects HTTP 200 HTML responses where `text/event-stream` or `application/json` is expected (`DiagnosticKey::NetworkCaptivePortal`).
- TCP keepalive (`15s`); dual idle timeouts: `300 s` before the first byte (slow-first-token reasoning models) and `90 s` between chunks. A stream that ends without the dialect terminal event (`response.completed|incomplete|failed`, `message_stop`, `interaction.completed`, Gemini `finishReason`, chat `finish_reason` / `[DONE]`) is `DiagnosticKey::ProviderStreamInterrupted`: an error when nothing arrived, otherwise the partial reply is kept with `interrupted: true` — never a silent "complete" truncation.

## 2. Big 3 + Custom Wire Dialects (Verified Nov 2026)
1. **Gemini Interactions API (`/v1beta/interactions`)**: Primary Gemini dialect (`step.start`/`step.delta`/`step.stop`, `thought_signature`/`thought_summary`). Defaults **`store: false`** (stateless canonical replay). Optional per-provider **"Server State Cache"** toggle enables `store: true` + `previous_interaction_id` mapped per DAG node with transparent stateless fallback on branch/edit/expiry/404. Legacy `generateContent` retained exclusively as a downgrade dialect for explicit caching or legacy proxies.
2. **OpenAI Responses API (`/v1/responses`)**: Primary OpenAI dialect. Defaults **`store: false`** with `include: ["reasoning.encrypted_content"]`. Optional opt-in `previous_response_id` state cache with transparent stateless fallback. `/v1/chat/completions` retained for OpenAI-compatible gateways/local servers.
3. **Anthropic Messages API (`/v1/messages`)**: Stateless by default. Uses automatic prompt caching (single top-level `cache_control` point), preserves opaque `thinking.signature` / `redacted_thinking` blocks strictly for same-model continuations, and supports readable `compaction` blocks.
4. **OpenAI-Compatible & Schema-Driven OpenAPI Async Media Queues**: Generic OpenAI-compatible chat/embeddings dialect plus OpenAPI 3.1 schema-driven async queue adapters (`fal.ai` submit/status/result).

- **Tool calls are captured once per provider id** (R1): a call repeated by the provider (`OpenAI` Responses sends a `function_call` in `output_item.done` and again in `response.completed`) is dropped by its raw id before the id is sanitized, so it never returns renamed (`call_42_2`) and runs twice. Distinct raw ids that sanitize alike stay distinct. Tests: `a_function_call_repeated_in_response_completed_is_captured_once`, `distinct_raw_ids_that_sanitize_alike_stay_distinct`.
- **Files uploaded for one request are always deleted** (R12): under `store: false`, provider files uploaded for a request are deleted after it on every path (success, error, Stop). Test: `an_ephemeral_upload_is_deleted_when_the_stream_fails`.

- **How a reply ended** (R10/P3, `crates/bistre-core/src/finish.rs`): each dialect's terminal frames map to one `FinishKind` (Stop, ToolUse, Length, PauseTurn, Refusal, Error{retryable, code}); values checked against the official docs on 2026-11-26 (the `OpenAI` `response.failed` payload is [UNVERIFIED]). Length raises `diag.provider.reply_truncated` and the composer offers Continue; Refusal raises `diag.provider.reply_refused`; an Anthropic `pause_turn` resumes by itself, sending the paused reply back as the last assistant turn (within the step limit). An error frame, or a plain JSON `{"error": …}` body on HTTP 200 (R42), is the real ending: without output, overload and server errors take the retry path (`ProviderStreamInterrupted`) and anything else fails at once (`ProviderRequestFailed`, `stream_error:<code>`), never retried for minutes; after output the reply is kept and marked interrupted. Tests: `finish::tests`, `providers::tests::a_plain_json_error_body_fails_with_the_providers_reason`, `a_reply_cut_by_the_output_limit_reports_length`, `egress_tests::a_truncated_reply_raises_the_truncated_notice`, `a_paused_anthropic_turn_resumes_by_itself`.
- **The provider's own reason** (P4): HTTP failures and error frames carry the provider's message in the detail (`;reason=…`, at most 200 characters, control characters and the `;`/`=` separators removed); the composer shows it under the error as "The provider said: …". Tests: `an_http_error_keeps_the_providers_reason`, `finish::tests::provider_reasons_are_bounded_and_cannot_forge_detail_fields`, `apps/bistre_app/test/reply_finish_test.dart`.
- **Facts from data, not code** (W4.8): each model's output limit comes from the price registry (`ModelRates::max_output_tokens`: `LiteLLM` `max_output_tokens`, models.dev `limit.output`, checked 2026-11-26; cache format 5), so Anthropic's required `max_tokens` is the model's own limit, with the old fixed value only as the fallback for an unknown model. The Anthropic wire constants (`anthropic-version`, the Files and context-management beta flags) live once in `bistre_protocol::dialect`. Provider quirks go by typed dialect only (no host-substring checks). The Write-mode story budget comes from the model's context window through one builder (`engine_story::story_prompt_report`, used by the run and the inspector; the old code used 32,000 and 16,384 for every model). Open: a per-model reasoning-effort vocabulary (pi `thinkingLevelMap`) needs a source that publishes it; until then the 400 heal ladder steps effort down. Tests: `registry::tests::output_limits_come_from_the_registry`, `engine_story::tests::the_story_budget_follows_the_models_context_window`.
- **One source of dialect facts** (P7, S4): `crates/bistre-protocol/src/dialect.rs` holds each format's `default_base_url`, `default_endpoint_path`, `models_path`, and `api_root` (a Gemini base already ending in `/v1beta` or `/v1` is reduced to the host, so paths are never doubled). Every request builder, `credentials::resolve_base_url`, and `resolve_endpoint` (the exact chat and model-list URLs, `ResolvedEndpoint`, P8) use it; the app reads it through FFI `provider_dialect_descriptors` and `resolve_provider_endpoint` and keeps no copy. Tests: `gemini_base_with_version_never_doubles_the_path`, `resolved_endpoints_match_the_urls_that_are_called`.
- **Web sources (grounding, B2)**: `crates/bistre-core/src/grounding.rs` parses the pages a reply used into `GroundingSource` (`http(s)` URL, title `<= 300` chars, cited text `<= 500`), deduplicated by URL, `<= 64` per reply, from any dialect's frames: Gemini `groundingMetadata.groundingChunks[].web.{uri,title}` (accumulated across stream chunks), `url_citation` annotations (OpenAI Responses completed items, Gemini Interactions), Anthropic `web_search_tool_result` / `web_search_result_location`. Wire shapes checked against the official docs on 2026-11-25; the OpenAI annotation stream event, the Anthropic `citations_delta` form, and the Chat Completions nesting are [UNVERIFIED]. Stored with the reply as `provider_meta_json.grounding = {"v": 1, "sources": [...]}` (another version reads as none); replay never sends it. `EngineClient::list_thread_grounding` / FFI `list_thread_grounding`. Tests: `grounding::tests`, `egress_tests::reply_sources_are_kept_for_the_chat_and_never_replayed`.

## 3. Reasoning Signature Compatibility & Prompt-Cache Preservation
- Every persisted reasoning/thinking blob stores `(provider_id, model_id, signature_blob)` in `nodes.provider_meta_json`. When projecting history to a different `(provider_id, model_id)`, foreign signature/thinking blocks are stripped automatically to avoid HTTP 400 rejections.
- Prompt assembly pins stable content first: `[System Prompt] -> [Deterministically Sorted Tool Schemas] -> [Canonical History] -> [Volatile Context / Lorebooks / Current Turn]` so prefix caches remain warm. W4.9: `prompt_surface_tests.rs` pins the cached prefix (tools, then the system prompt wherever the dialect carries it) with a golden per dialect in `crates/bistre-core/fixtures/prompt_surface/`, asserts it is byte-identical as the conversation grows (no volatile value in the hashed prefix, hermes #144442), and checks Anthropic's cache breakpoints (last tool, system block) on the converted wire body (SillyTavern #5227). Refresh with `BISTRE_UPDATE_GOLDENS=1` and review the diff.
- **Every tool call has a result** (pi #9986, cherry-studio #24997): before each request `replay_policy::answer_dangling_tool_calls` gives a call left without a result (a stopped or crashed run) an error result "This tool call did not run" right after its turn, so providers never reject a dangling `tool_use` and the model knows it did not run. Test: `replay_policy::tests::a_dangling_tool_call_gets_a_did_not_run_result`.
- **No empty assistant turns** (R13): an assistant turn with no text and no tool call (a stopped reply that only thought) is left out of the request. Test: `compaction::tests::an_empty_assistant_turn_is_never_replayed`.
- **Reasoning is gated per turn, not per chat** (R14): a compaction only invalidates opaque reasoning made before the newest summary (`replay_policy::made_before_compaction`); turns made after it keep their blocks. Dropping reasoning to heal one 400 marks the model "no reasoning" only when the provider said reasoning is unsupported (`error_policy::says_reasoning_unsupported`; a signature 400 never does; other cases use the code `heal_drop_reasoning_once`). Tests: `reasoning_made_after_the_compaction_is_still_replayable`, `only_an_unsupported_reasoning_error_marks_the_model`.
- **No null fields on replay** (codex #47733): stored `OpenAI` reasoning summaries are sent back without `null` members. Test: `wire_history::tests::replayed_reasoning_items_carry_no_null_fields`.
- **`OpenAI` Responses prompt and calls** (G1/G2, checked against the `OpenAI` prompt-caching guide and the Responses reference on 2026-11-26): newer models append top-level `instructions` after `input`, so the system prompt is sent as a `developer` message first in `input`, inside the cached prefix; replayed `function_call` items carry the documented `status: "completed"`. Whether a missing `status` drops reasoning (pi #12367) is [UNVERIFIED]. Test: `providers::tests::openai_responses_put_the_system_prompt_first_and_replay_call_status`.
- **Stateful chaining** (R7, `replay_policy::chain_plan`): `previous_response_id` / `previous_interaction_id` is sent only when this request stores (`store`, one decision the run shares with the body: the provider's server-state cache or Settings > Advanced "store on the provider") and the history is uncompacted; the request then sends only the items after the chained reply (pairing still sees the whole history, so a tool result after a chained call goes out) and, for `OpenAI`, no `developer` prompt item (it stays in the stored conversation). Tests: `chaining_needs_storing_and_sends_only_the_new_items`, `a_chained_openai_request_does_not_resend_the_system_prompt`, `a_chained_request_after_a_tool_call_sends_the_result`.
- **Gemini `thoughtSignature`** (ported from kelivo's signature fixtures, `gemini_signature_tests.rs`): a signature on a text part (often a trailing empty one) is stored as `GeminiTextSignature` and sent back on the text part, or as its own empty text part after the calls; a call keeps only its own signature (in parallel calls only the first is signed, and an unsigned call never borrows one); on replay the first call of a turn always carries a signature (its own or the documented bypass) and later calls only their own.

## 4. Negative Capability Cache & Auto-Downgrade Ladder
Unsupported features (e.g., structured outputs, strict tools, reasoning effort, streaming usage) are cached negatively by `(endpoint_hash, model_id, capability)` with a monotonic `24h` TTL and stepped down cleanly without repeat 400 round trips.

## 5. 5-Class Self-Healing Engine (Subordinate to Wallet Shield)
1. **Class 1 — Parameter/Schema Rejection**: Parse provider 400 field diagnostics, strip/clamp unsupported parameter, update negative capability cache, retry once.
2. **Class 2 — Reversible Branch-Safe Context Compaction**: Create a local readable `compaction_summary` DAG node pointing to raw SQLite evidence; pin non-negotiable safety rules & verification receipts outside summaries (preventing Compaction Cliff / epistemic drift). Never overwrite or delete prior branch nodes.
3. **Class 3 — Stream Drop / Truncation**: Reconnect with monotonic backoff; never silently fabricate missing output.
4. **Class 4 — Malformed Tool Call / Stale Edit Hash**: Return structured tool error (`DiagnosticKey::ToolEditHashMismatch` + fresh file excerpt/hashes) back to model within bounded turn budget.
5. **Class 5 — Rate Limits / 5xx**: Respect `Retry-After` headers + jittered exponential backoff within configured ceiling.

**Wallet Shield Precedence**: Wallet Shield unconditionally overrides all 5 classes. Paid async media submits use WAL-before-POST (`PENDING_SUBMIT` → `INDETERMINATE_HALT` on transport drop) and NEVER auto-retry without explicit user reconciliation.

## 6. Single Dispatch Path, Keys, Retries & Heal Ladder (`providers::dispatch`)
- **One dispatch path** for chat and `/models`: `WireRequest` URLs are credential-free; the key is attached per attempt as a header (`Authorization: Bearer`, `x-goog-api-key`, `x-api-key`). Any future query-parameter auth must be appended last with `url.query_pairs_mut().append_pair` so keys never appear in a loggable URL string.
- **No redirects on the provider client** (`http_clients::provider_client`, R6): a redirect response is an error. A cross-host redirect would otherwise carry `x-api-key` / `x-goog-api-key` (reqwest strips only `Authorization`) and, for 307/308, the request body. Update feeds and artifacts use a separate credential-free `ota_client` that follows at most `6` redirects, each to `https` or a loopback test host. Tests: `providers::tests::a_cross_host_redirect_never_forwards_the_key_or_the_body`, `http_clients::tests::ota_redirects_only_to_https_or_loopback`.
- **Custom headers and body fields** (`crates/bistre-core/src/custom_headers.rs`, A-S8): parsed once into `CustomHeader`s, which only `parse_custom_headers` can build: a JSON object of string names to string values, at most `32`, RFC 9110 token names, no reserved/credential/connection headers (`authorization`, `x-api-key`, `x-goog-api-key`, `api-key`, `cookie`, `host`, `content-type`, `accept`, `anthropic-version`, `anthropic-beta`, ...), no control characters (a line break is refused as injection), printable ASCII after zero-width characters are removed, values `<= 4 KiB`. The body must be a JSON object (`<= 64 KiB`). `save_provider_overrides` validates before saving and binds the headers to the provider origin; changing the base URL to another origin clears them (`diag.provider.headers_cleared`). An invalid stored entry stops the request before any reservation or send (`diag.provider.headers_invalid` / `diag.provider.body_invalid`), never a silent drop. Tests: `custom_headers::tests`, `egress_tests`.
- **Pinned providers** (R19): a provider chosen by the chat or its assistant is used or the request fails with `diag.provider.pinned_unavailable` (turned off, removed, or no key); only the global default may fall back to the first configured provider. Test: `egress_tests::a_pinned_provider_that_is_off_never_falls_back_to_another`.
- **Live voice and read aloud keys** (A-S10): keys rotate like other requests and a missing key fails closed. Gemini Live accepts an API key only as the `key` query parameter (an `x-goog-api-key` header is not accepted; Live API WebSocket guide, verified 2026-11-25), so that one URL carries the key: it is URL-encoded, the session is refused over plain `ws` to a non-loopback host (`live_insecure_transport`), and the URL is never logged. `OpenAI` Realtime keeps the base path and URL-encodes the model. Test: `voice::tests::live_targets_encode_secrets_and_refuse_insecure_public_hosts`.
- **Multiple keys per provider** (`crates/bistre-core/src/credentials.rs`): pasted text may hold several keys (one per line or comma separated, max `16`), sanitized of `\r`, `\n`, zero-width characters, the BOM, and control characters, stored together in the OS `SecretVault`. Requests start at a process-wide round-robin index (`API_KEY_RR`) and fail over to the remaining keys immediately on `401` / `403` / `429` before any backoff (notice `key_failover_N_of_M`). The key hint reads `••••a1b2 (+2)`.
- **Failure classification & hints** (`crates/bistre-core/src/error_policy.rs`): `retry-after-ms` → `retry-after` (seconds or RFC 7231 IMF-fixdate) → Gemini `RetryInfo.retryDelay` (first 64 KiB of the body), at least `1 s`; a zero `retry-after-ms` is no hint, so `retry-after` decides (G4, opencode #63174). There is no upper clamp: a hint longer than the retry budget left makes the run give up at once instead of retrying early into the same limit (R32). Billing/credit stops, `PerDay` quota failures, and spend caps (`ProviderQuotaExhausted`) are never retried; transient-worded 400s are retryable. Typed keys drive jump-to-fix UI: `ProviderAuthFailed`, `ProviderRateLimited`, `ProviderQuotaExhausted`, `ProviderContextOverflow`.
- **HTTP 400 heal ladder** (`MAX_HTTP_400_HEALS = 6` resends, first applicable step wins, each raised as `ProviderRequestHealed` + detail code): strip Anthropic `thinking.display` → Gemini `thinkingLevel` → `thinkingBudget` → reasoning effort step-down (`max → xhigh → high`, `minimal → low`) → strip `stream_options` → toggle `max_completion_tokens` ↔ `max_tokens` → strip non-function built-in tools → strip `temperature`/`top_p` → drop reasoning. Gemini Interactions `400`/`404` still downgrades once to `streamGenerateContent`.
- **Run-loop recovery** (`execute_durable_stream_loop`): `ProviderContextOverflow` (`413` or context-length markers) triggers one in-flight reversible compaction and a single retry; rate limits, transient `5xx`/`408`/`409`/`425`, connect failures, and streams that died before any output back off via `compute_backoff_wait_ms` within `retry_watchdog_max_wait_secs` (wall-clock since the first failure of the streak, so `Retry now` spends only the time that passed; jitter seeded per run, so runs that failed together do not retry together; one backoff per provider shared by every run, `provider_backoff.rs`, which `Retry now` clears; a `404` such as a wrong base URL is never retried), emitting `RunBackoffWaiting` (`retry_in_ms=…`). `EngineClient::retry_run_now` (and cancel) wake the wait instantly through a per-thread `tokio::sync::Notify`. Mid-stream retry never happens after partial output (no duplicated text or double billing): an idle timeout or body read error after any text or thinking returns the kept reply with `interrupted = true` instead of `ProviderStreamInterrupted`, gated by `error_policy::may_retry_stream` (test `a_stream_that_breaks_after_output_is_kept_not_retried`). A stream silent for 15 s when the app comes back (`SystemPowerEvent::AppResumed`, also on system wake) ends at once as interrupted instead of waiting out its idle timeout (P19, test `a_stream_stalled_across_a_resume_ends_when_the_app_comes_back`); `app_resumed` never touches run journals. Stop takes effect within `CANCEL_POLL_INTERVAL` (50 ms) even while connecting or waiting for the first token: `dispatch()` and every chunk wait race `until_cancelled` (test `stop_interrupts_a_request_waiting_for_its_first_token`).
- **History hygiene**: replay sends only user/assistant/summary turns (UI interruption state lives in `provider_meta_json`, never in content); `compaction::enforce_role_alternation` merges consecutive same-role turns and drops assistant tails before dispatch; tool-call IDs are sanitized to `[A-Za-z0-9_-]{1,64}` and de-duplicated (`tools::sanitize_tool_call_id`).
- **Deferred until native tool / reasoning replay lands** (contract, not yet code): `tools` must serialize first in request bodies (enable `serde_json/preserve_order`), opaque signatures replay only for the same provider + model + dialect with a Franken-signature guard on Gemini chunks, cross-provider reasoning handoff is clipped to `8,000` chars (25% head / 75% tail), and historical tool outputs compact in quantized batches of `16`.
- **Property test**: `chunk_boundaries_never_change_the_events` (`crates/bistre-core/src/sse.rs`, `proptest 1.12`, test-only dependency) checks that any split of an SSE byte stream yields the same events as the whole stream.

## Thinking Effort (2026-11-24)
`GenerationParams.reasoning_effort` is a typed `ReasoningEffort`: `ModelDefault`, `Off`, `Low`, `Medium`, `High`, `ExtraHigh`, or `Max`. It is parsed once from the `reasoning_effort` setting (`default`, `off`, `low`, `medium`, `high`, `xhigh`, `max`), and the default sends nothing. It reaches the wire only when the registry marks the model reasoning-capable (Spec 03); otherwise a model that cannot think would reject it with a 400 on every message. Field names below were verified against the live docs on 2026-11-24 unless marked otherwise.

| Dialect | Field | Off | Low to Max |
|---|---|---|---|
| OpenAI Responses | `reasoning: {effort, summary: "auto"}` | `none` | `low`, `medium`, `high`, `xhigh`, `max` |
| OpenAI-compatible Chat | `reasoning_effort` | `none` | as above |
| Anthropic Messages | `thinking: {type: "adaptive", display: "summarized"}` + `output_config: {effort}` | `thinking: {type: "disabled"}` `[UNVERIFIED]` | `low` to `max` |
| Gemini Interactions | `generation_config: {thinking_level, thinking_summaries}` | `low` + summaries `none` | `low`, `medium`, `high`, `xhigh` (Max maps to `xhigh`) |
| Gemini generateContent (fallback) | `generationConfig.thinkingConfig: {includeThoughts, thinkingLevel}` `[UNVERIFIED]` | `LOW`, thoughts hidden | uppercase levels |

The 400 heal ladder covers each field:
- `StepDownReasoningEffort` steps `reasoning.effort`, `reasoning_effort`, `output_config.effort`, and `generation_config.thinking_level` down (`max`→`xhigh`→`high`).
- `DropReasoning` removes `reasoning`, `reasoning_effort`, `thinking`, `output_config`, `thinkingConfig`, `thinking_level`, and `thinking_summaries`.

Tests: `providers_tests::reasoning_effort_reaches_each_dialect_in_its_own_wire_field` and `error_policy::tests::effort_heals_cover_anthropic_and_gemini_interactions_fields`.
