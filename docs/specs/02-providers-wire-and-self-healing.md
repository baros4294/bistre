# Spec 02: Providers, Wire Protocols & 5-Class Self-Healing Engine

## 1. Zero Third-Party LLM SDKs & Pure-Rust TLS Transport
All provider adapters run in `crates/bistre-core` (`crates/bistre-core/src/providers.rs`) on `reqwest 0.13` + `rustls 0.23` (`ring` crypto provider) + `rustls-platform-verifier 0.7.1` (honoring OS/enterprise CA trust stores and system proxies; `openssl-sys` and `aws-lc-sys` banned via `deny.toml`).
- API keys are retrieved strictly from the node-local encrypted OS `SecretVault` (`LocalSecretVault` in `crates/bistre-crypto`, using Windows DPAPI `CryptProtectData`/`CryptUnprotectData` with in-place zeroization on drop). When no provider is configured, Bistre returns `DiagnosticKey::ProviderNotConfigured` and never fabricates fake mock AI replies.
- Live `/models` discovery fetches model lists on demand from each provider's API (zero hardcoded model tables per Spec 03) alongside manual model ID entry.
- Live Generation Parameters & SSE Usage Accounting: `GenerationParams` (`temperature`, `max_output_tokens`/`max_tokens`, `top_p`) resolved via `Thread override → Assistant default → provider default` are forwarded natively across OpenAI Responses, Gemini, Anthropic Messages, and OpenAI-Compatible streams (`stream_options: { include_usage: true }`). Real input/output token counts are extracted from SSE payloads, persisted onto `nodes.provider_meta_json`, and converted into exact integer `MoneyMicros` entries in `wallet_ledger` (`$0.00` automatically for loopback local servers).
- `SseFramer` (`crates/bistre-core/src/sse.rs`): UTF-8 carry-over across chunks; BOM stripped at stream start only; single-line complete-JSON `data:` frames dispatched immediately (no wait for the blank separator); `\r\n` / `\n` / lone `\r` endings with a held-back trailing `\r`; plain-JSON body fallback when the upstream ignores `stream: true`; hard 64 MiB buffer cap. Each byte is searched for a line ending once (a `scanned` cursor), so a long line split over many chunks costs linear time (16 MiB in 16 KiB chunks: 317 s before, under 1 s after; test `a_long_line_in_many_chunks_is_scanned_in_linear_time` checks the cursor after every chunk, so load cannot fail it). A cap hit follows the dropped-stream rule: retried only when nothing was shown, otherwise the output is kept and the reply marked interrupted (test `a_buffer_cap_after_output_marks_the_reply_interrupted_instead_of_retrying`). `StreamingTextBuffer` normalizes split `\r` + `\n` in text deltas before they reach the UI.
- Captive portal guard rejects HTTP 200 HTML responses where `text/event-stream` or `application/json` is expected (`DiagnosticKey::NetworkCaptivePortal`).
- TCP keepalive (15s); dual idle timeouts: 300 s before the first byte (slow-first-token reasoning models) and 90 s between chunks. A stream that ends without the dialect terminal event (`response.completed|incomplete|failed`, `message_stop`, `interaction.completed`, Gemini `finishReason`, chat `finish_reason` / `[DONE]`) is `DiagnosticKey::ProviderStreamInterrupted`: an error when nothing arrived, otherwise the partial reply is kept with `interrupted: true`: never a silent "complete" truncation.

## 2. Big 3 + Custom Wire Dialects (Verified Nov 2026)
1. Gemini Interactions API (`/v1beta/interactions`): Primary Gemini dialect (`step.start`/`step.delta`/`step.stop`, `thought_signature`/`thought_summary`). Defaults `store: false` (stateless canonical replay). Optional per-provider "Server State Cache" toggle enables `store: true` + `previous_interaction_id` mapped per DAG node with transparent stateless fallback on branch/edit/expiry/404. Legacy `generateContent` retained exclusively as a downgrade dialect for explicit caching or legacy proxies.
2. OpenAI Responses API (`/v1/responses`): Primary OpenAI dialect. Defaults `store: false` with `include: ["reasoning.encrypted_content"]`. Optional opt-in `previous_response_id` state cache with transparent stateless fallback. `/v1/chat/completions` retained for OpenAI-compatible gateways/local servers.
3. Anthropic Messages API (`/v1/messages`): Stateless by default. Uses automatic prompt caching (single top-level `cache_control` point), preserves opaque `thinking.signature` / `redacted_thinking` blocks strictly for same-model continuations, and supports readable `compaction` blocks.
4. OpenAI-Compatible & Schema-Driven OpenAPI Async Media Queues: Generic OpenAI-compatible chat/embeddings dialect plus OpenAPI 3.1 schema-driven async queue adapters (`fal.ai` submit/status/result).

- `OpenRouter` (checked against its reasoning tokens, provider selection, and models list docs): a fourth starter provider, a plain `OpenAI`-compatible profile (`openrouter`, base `https://openrouter.ai/api/v1`, Bearer key) with no settings of its own. It is seeded once per database (`providers_seeded_openrouter`), so an existing database gets it once and a deleted one never returns. A profile whose base URL is HTTPS on `openrouter.ai` or a subdomain (`dialect::is_openrouter_base`, a parsed host, never a substring) needs a key (`ProviderProfile::requires_api_key`, so the keyless starter is never picked as a fallback), lists models from `/models/user` once keyed (the models the account's privacy and provider settings allow), and is the only target that gets `OpenRouter`-only fields: `provider: { "data_collection": "deny" }` on every request (a custom body field may override it) and replayed `reasoning_details`. No attribution headers are sent. Model ids and prices come from the live catalog and the registry only. Tests: `dialect::tests::only_https_on_the_openrouter_host_or_a_subdomain_is_openrouter`, `request_body::tests::openrouter_only_fields_go_to_openrouter_only`, storage `tests` (starters).
- `OpenRouter` `reasoning_details` (`crates/bistre-core/src/reasoning_details.rs`): streamed entries are kept as raw JSON (every field, no fixed `type` or `format` list) in one `OpenRouterDetails` block. Fragments of one `index` and `type` join (their `text`, `summary`, and `signature` concatenate); an encrypted entry, a changed `type` or `id`, or a fragment without `index` starts a new entry, so distinct encrypted blocks never merge; at most 256 entries per reply. The thought is shown once: from the plain `reasoning` string, else from the readable entries, never from encrypted data and never the `[REDACTED]` placeholder. On an assistant tool-call turn the entries go back unmodified and in order when the target provider, model, system prompt, and tools match the turn's origin and no compaction rewrote its prefix; otherwise only entries that are neither `reasoning.encrypted` nor signed go. Tests: `reasoning_details::tests`, `wire_stream::tests::{openrouter_reasoning_details_are_kept_raw_and_shown_once, the_redacted_placeholder_is_never_shown}`, `wire_history::tests::openrouter_reasoning_details_replay_only_to_openrouter`.

- Tool calls are captured once per provider id: a call repeated by the provider (`OpenAI` Responses sends a `function_call` in `output_item.done` and again in `response.completed`) is dropped by its raw id before the id is sanitized, so it never returns renamed (`call_42_2`) and runs twice. Distinct raw ids that sanitize alike stay distinct. Responses calls are accumulated by `output_index`, so calls from a gateway that omits item ids never merge; a Chat Completions function name resent whole on each chunk is not doubled. Tests: `a_function_call_repeated_in_response_completed_is_captured_once`, `distinct_raw_ids_that_sanitize_alike_stay_distinct`, `responses_calls_without_ids_stay_separate_by_output_index`, `a_resent_chat_function_name_is_not_doubled`.
- Files uploaded for one request are always deleted: under `store: false`, provider files uploaded for a request are deleted after it on every path (success, error, Stop). Test: `an_ephemeral_upload_is_deleted_when_the_stream_fails`.

- How a reply ended (`crates/bistre-core/src/finish.rs`): each dialect's terminal frames map to one `FinishKind` (Stop, ToolUse, Length, PauseTurn, Refusal, Error{retryable, code}); values checked against the official docs (the `OpenAI` `response.failed` payload is [UNVERIFIED]). Length raises `diag.provider.reply_truncated` and the composer offers Continue; Refusal raises `diag.provider.reply_refused`; an Anthropic `pause_turn` resumes by itself, sending the paused reply back as the last assistant turn (within the step limit). An error frame, or a plain JSON `{"error": …}` body on HTTP 200, is the real ending: without output, overload and server errors take the retry path (`ProviderStreamInterrupted`) and anything else fails at once (`ProviderRequestFailed`, `stream_error:<code>`), never retried for minutes; after output the reply is kept and marked interrupted. Tests: `finish::tests`, `providers::tests::a_plain_json_error_body_fails_with_the_providers_reason`, `a_reply_cut_by_the_output_limit_reports_length`, `egress_tests::a_truncated_reply_raises_the_truncated_notice`, `a_paused_anthropic_turn_resumes_by_itself`.
- The provider's own reason: HTTP failures and error frames carry the provider's message in the detail (`;reason=…`, at most 200 characters, control characters and the `;`/`=` separators removed); the composer shows it under the error after "The provider said:". Tests: `an_http_error_keeps_the_providers_reason`, `finish::tests::provider_reasons_are_bounded_and_cannot_forge_detail_fields`, `apps/bistre_app/test/reply_finish_test.dart`.
- Facts from data, not code: each model's output limit comes from the price registry (`ModelRates::max_output_tokens`: OpenRouter `top_provider.max_completion_tokens`, `LiteLLM` `max_output_tokens`; Spec 03), so Anthropic's required `max_tokens` is the model's own limit, with the old fixed value only as the fallback for an unknown model. The Anthropic wire constants (`anthropic-version`, the Files and context-management beta flags) live once in `bistre_protocol::dialect`. Provider quirks go by typed dialect only (no host-substring checks), except the one parsed-host check for `OpenRouter`. The Write-mode story budget comes from the model's context window through one builder (`engine_story::story_prompt_report`, used by the run and the inspector; the old code used 32,000 and 16,384 for every model). Open: a per-model reasoning-effort vocabulary (pi `thinkingLevelMap`) needs a source that publishes it; until then the 400 heal ladder steps effort down. Tests: `registry::tests::output_limits_come_from_the_registry`, `engine_story::tests::the_story_budget_follows_the_models_context_window`.
- One source of dialect facts (S4): `crates/bistre-protocol/src/dialect.rs` holds each format's `default_base_url`, `default_endpoint_path`, `models_path`, and `api_root` (a Gemini base already ending in `/v1beta` or `/v1` is reduced to the host, so paths are never doubled). Every request builder, `credentials::resolve_base_url`, and `resolve_endpoint` (the exact chat and model-list URLs, `ResolvedEndpoint`) use it; the app reads it through FFI `provider_dialect_descriptors` and `resolve_provider_endpoint` and keeps no copy. Tests: `gemini_base_with_version_never_doubles_the_path`, `resolved_endpoints_match_the_urls_that_are_called`.
- Web sources (grounding): `crates/bistre-core/src/grounding.rs` parses the pages a reply used into `GroundingSource` (`http(s)` URL, title ≤ 300 chars, cited text ≤ 500), deduplicated by URL, ≤ 64 per reply, from any dialect's frames: Gemini `groundingMetadata.groundingChunks[].web.{uri,title}` (accumulated across stream chunks), `url_citation` annotations (OpenAI Responses completed items, Gemini Interactions), Anthropic `web_search_tool_result` / `web_search_result_location`. Wire shapes checked against the official docs; the OpenAI annotation stream event, the Anthropic `citations_delta` form, and the Chat Completions nesting are [UNVERIFIED]. Stored with the reply as `provider_meta_json.grounding = {"v": 1, "sources": [...]}` (another version reads as none); replay never sends it. `EngineClient::list_thread_grounding` / FFI `list_thread_grounding`. ## 3. Reasoning Signature Compatibility & Prompt-Cache Preservation
- Every assistant turn stores its origin `(dialect, provider_id, model_id, system_hash, tools_hash)` in `nodes.provider_meta_json`. Opaque payloads (`OpenAI` `encrypted_content`, Anthropic thinking signatures and redacted thinking, Gemini thought signatures, encrypted or signed `OpenRouter` entries) replay only to that exact origin with an uncompacted prefix (`replay_policy::can_replay_opaque_reasoning`); any switch strips them and keeps the visible text and turn order. A Gemini target gets the documented bypass signature on a foreign call, and the 400 heal ladder strips signatures if a provider still refuses. The latest switched turn's plain thinking goes along as a bounded `[Prior reasoning summary]`, on a provider switch with the same model id too. Compaction summaries are plain user-role text on every dialect. Tests: `opaque_reasoning_replays_only_on_exact_same_origin_and_unchanged_prefix`, `a_provider_switch_with_the_same_model_id_gets_the_handoff`.
- Tool-call ids on replay (`tool_call_ids::ToolIdPlan`): a result pairs with the latest earlier open call of its id, and an unpaired call or result is not sent. A paired id that is unique in the history and `[A-Za-z0-9_-]{1,64}` goes as stored (a same-model replay keeps every link to it); any other pair (a reused `call_0` from a provider that sends no ids) gets one deterministic new id for both call and result. Arguments that are not a JSON object replay to Anthropic and Gemini as `{"INVALID_JSON": raw}` next to the error result. Tests: `reused_call_ids_across_turns_are_remapped_as_pairs`, `invalid_tool_arguments_are_replayed_raw_never_as_empty_objects`.
- Prompt assembly pins stable content first: `[System Prompt] -> [Deterministically Sorted Tool Schemas] -> [Canonical History] -> [Volatile Context / Lorebooks / Current Turn]` so prefix caches remain warm. `prompt_surface_tests.rs` pins the cached prefix (tools, then the system prompt wherever the dialect carries it) with a golden per dialect in `crates/bistre-core/fixtures/prompt_surface/`, asserts it is byte-identical as the conversation grows (no volatile value in the hashed prefix), and checks Anthropic's cache breakpoints (last tool, system block) on the converted wire body. Refresh with `BISTRE_UPDATE_GOLDENS=1` and review the diff.
- Every tool call has a result: before each request `replay_policy::answer_dangling_tool_calls` gives a call left without a result (a stopped or crashed run) an error result "This tool call did not run" right after its turn, so providers never reject a dangling `tool_use` and the model knows it did not run. Test: `replay_policy::tests::a_dangling_tool_call_gets_a_did_not_run_result`.
- No empty assistant turns: an assistant turn with no text and no tool call (a stopped reply that only thought) is left out of the request. Test: `compaction::tests::an_empty_assistant_turn_is_never_replayed`.
- Reasoning is gated per turn, not per chat: a compaction only invalidates opaque reasoning made before the newest summary (`replay_policy::made_before_compaction`); turns made after it keep their blocks. Dropping reasoning to heal one 400 marks the model "no reasoning" only when the provider said reasoning is unsupported (`error_policy::says_reasoning_unsupported`; a signature 400 never does; other cases use the code `heal_drop_reasoning_once`). Tests: `reasoning_made_after_the_compaction_is_still_replayable`, `only_an_unsupported_reasoning_error_marks_the_model`.
- No null fields on replay: stored `OpenAI` reasoning summaries are sent back without `null` members. Test: `wire_history::tests::replayed_reasoning_items_carry_no_null_fields`.
- `OpenAI` Responses prompt and calls (checked against the `OpenAI` prompt-caching guide and the Responses reference): newer models append top-level `instructions` after `input`, so the system prompt is sent as a `developer` message first in `input`, inside the cached prefix; replayed `function_call` items carry the documented `status: "completed"`. Whether a missing `status` drops reasoning is [UNVERIFIED]. Test: `providers::tests::openai_responses_put_the_system_prompt_first_and_replay_call_status`.
- Stateful chaining (`replay_policy::chain_plan`): `previous_response_id` / `previous_interaction_id` is sent only when this request stores and the history is uncompacted. Whether a request stores is one decision (`provider_prefs::stores_on_server`) that the request body, chaining, and the saved reply share: never while Settings → Safety & Budget → Private requests is on (the default), otherwise the provider's Allow server-side storage switch in its Advanced settings (requests outside a chat run never store); the request then sends only the items after the chained reply (pairing still sees the whole history, so a tool result after a chained call goes out) and, for `OpenAI`, no `developer` prompt item (it stays in the stored conversation). Tests: `chaining_needs_storing_and_sends_only_the_new_items`, `a_chained_openai_request_does_not_resend_the_system_prompt`, `a_chained_request_after_a_tool_call_sends_the_result`.
- Gemini `thoughtSignature` (ported from kelivo's signature fixtures, `gemini_signature_tests.rs`): a signature on a text part (often a trailing empty one) is stored as `GeminiTextSignature` and sent back on the text part, or as its own empty text part after the calls; a call keeps only its own signature (in parallel calls only the first is signed, and an unsigned call never borrows one); on replay the first call of a turn always carries a signature (its own or the documented bypass) and later calls only their own.

## 4. Negative Capability Cache & Auto-Downgrade Ladder
Unsupported features (e.g., structured outputs, strict tools, reasoning effort, streaming usage) are cached negatively by `(endpoint_hash, model_id, capability)` with a monotonic 24h TTL and stepped down cleanly without repeat 400 round trips.

## 5. 5-Class Self-Healing Engine (Subordinate to Wallet Shield)
1. Class 1: Parameter/Schema Rejection: Parse provider 400 field diagnostics, strip/clamp unsupported parameter, update negative capability cache, retry once.
2. Class 2: Reversible Branch-Safe Context Compaction: Create a local readable `compaction_summary` DAG node pointing to raw SQLite evidence; pin non-negotiable safety rules & verification receipts outside summaries (preventing Compaction Cliff / epistemic drift). Never overwrite or delete prior branch nodes.
3. Class 3: Stream Drop / Truncation: Reconnect with monotonic backoff; never silently fabricate missing output.
4. Class 4: Malformed Tool Call / Stale Edit Hash: Return structured tool error (`DiagnosticKey::ToolEditHashMismatch` + fresh file excerpt/hashes) back to model within bounded turn budget.
5. Class 5: Rate Limits / 5xx: Respect `Retry-After` headers + jittered exponential backoff within configured ceiling.

Wallet Shield Precedence: Wallet Shield unconditionally overrides all 5 classes. Paid media requests reserve before they are sent, are never retried, and book their reservation once sent if they fail or are stopped (§7, ADR-0019); a cut-off video job is booked at the next launch and fetched again by Try again (ADR-0019 Decision 9).

## 6. Single Dispatch Path, Keys, Retries & Heal Ladder (`providers::dispatch`)
- One dispatch path for chat and `/models`: `WireRequest` URLs are credential-free; the key is attached per attempt according to `AuthMode` (`Native`: `Authorization: Bearer`, `x-goog-api-key`, `x-api-key`; `Bearer`: `Authorization: Bearer` for any dialect; `Query`: appended last at send time with `url.query_pairs_mut().append_pair("key", ...)` so stored and logged URLs stay credential-free).
- Provider tools (Advanced > Use {name}'s own tools, `providerTools`, off by default; shown only for the Gemini Interactions and Anthropic Messages formats): the provider's tools that cost nothing beyond tokens are sent beside Bistre's (`request_body::provider_tools`): Gemini `{type: "url_context"}` and `{type: "code_execution"}`; Anthropic `web_fetch_20260318` (`max_uses` `MAX_PROVIDER_FETCHES` = 5, `max_content_tokens` `MAX_PROVIDER_FETCH_TOKENS` = 20,000; it takes the place of Bistre's `web_fetch`, since a request holds a tool name once) and `code_execution_20260521`, which has no charge while that `web_fetch` version is in the request. They go only when Bistre's tools are sent and no spending limit applies (Spec 06). A provider or model that rejects them gets them stripped by the HTTP 400 heal `StripBuiltinTools`, and the Gemini `generateContent` downgrade sends Bistre's tools only. Paid provider tools (Advanced > Use {name}'s paid web search, `paidProviderTools`, off by default; Anthropic Messages and OpenAI Responses only; `crates/bistre-core/src/paid_tools.rs`): Anthropic `web_search_20250305` (`max_uses` 5) or OpenAI `{type: "web_search"}` takes the place of Bistre's `web_search`, and OpenAI also gets `{type: "code_interpreter", container: {type: "auto"}}`. Each goes only beside Bistre's tools and only when the catalog prices the call (LiteLLM `search_context_cost_per_query`, the dearest size, and `code_interpreter_cost_per_session`); the reply's count (Anthropic `usage.server_tool_use.web_search_requests`, OpenAI `web_search_call` items and distinct `code_interpreter_call` containers) is billed on top of tokens (Spec 06). Google Search grounding is not sent: Bistre reads no per-search count from a Gemini reply. Tests: `paid_tools::tests`. Their results stay on the provider's side: the reply's text and `url_citation` sources (Spec 02 web sources) are kept, and replay sends neither. Request shapes checked against the official docs; replaying Gemini stateless turns that used them is `[UNVERIFIED]`. Tests: `request_body::tests::{provider_tools_join_bistre_tools_only_where_free_and_turned_on, the_400_heal_strips_provider_tools_and_keeps_bistres}`, `turn_context::tests::any_spending_limit_counts_and_an_unreadable_one_counts_too`.
- Advanced rows follow the API format requests use (`ProviderAdvancedConfig.wireFor`): Keep replies on the server and its chaining for OpenAI Responses and Gemini Interactions, the hour-long prompt cache and server compaction for Anthropic Messages, the `generateContent` fallback for Gemini, so a Custom provider speaking Chat Completions shows none of them. Test: `apps/bistre_app/test/provider_advanced_test.dart`.
- Provider advanced wire options (`provider_prefs::ProviderAdvancedPrefs`): a Custom provider speaks the API format chosen in Advanced (`speaking()` routes chat and `/models` through OpenAI Responses, Anthropic Messages, or Gemini Interactions instead of Chat Completions); a validated `endpoint_path` (leading `/`, ≤ 256 bytes, no scheme/host/query/fragment/`..`/whitespace) replaces the dialect's default request path; `fetch_models_with_auth` uses the provider's chosen `AuthMode` on `/models`; `defaultThinkingEffort` supplies the provider's default thinking level whenever the global/composer effort is `Auto` (still gated by catalog/runtime reasoning support); per-model `modelOverrides` (`contextLimit`, `maxOutputTokens`, and USD/1M prices including `reasoningPerMillion`, parsed in integer micro-USD) feed context breakdown, proactive compaction, story prompt budget, reply `max_tokens`, and Wallet Shield reservations/settlement (fail-closed: a limits-only override on an unpriced model keeps pricing unknown); Anthropic Advanced exposes `anthropicCache1h` (1-hour prompt cache TTL) and `enableServerCompaction` (server-side compaction beta header). Tests: `provider_prefs::tests::{a_custom_provider_speaks_its_chosen_format, model_overrides_feed_limits_and_wallet_rates_fail_closed}`, `providers::tests::the_advanced_endpoint_path_and_authentication_are_used`, `egress_tests::{provider_advanced_model_overrides_feed_limits, provider_advanced_default_thinking_effort_reaches_the_wire, provider_advanced_fetch_models_uses_auth_mode_and_custom_dialect}`, `apps/bistre_app/test/provider_advanced_test.dart`.
- Provider share codes (`provider_prefs::{export,import}_provider_share_code`): `ai-provider:v1:` + URL-safe base64 JSON of the name, API format, server URL, default model, the Custom API format (one `CUSTOM_DIALECTS` table read by both the loader and the exporter, so a code keeps `anthropic_messages` and the like), endpoint path and sign-in mode; the key only when asked. Import fails closed on a wrong prefix, more than 16 KiB, bad base64 or JSON, a non-`http(s)` URL, or an empty name, and always creates a new provider. Tests: `provider_prefs::tests::provider_share_code_excludes_api_key_by_default_and_validates_url`, `egress_tests::a_provider_share_code_keeps_the_api_format_and_leaves_the_key_out`.
- Raw request and response (`crates/bistre-core/src/raw_exchange.rs`): the credential-free URL and body of the latest `MAX_RAW_EXCHANGES` (16) chat requests and the bytes their responses streamed, each capped at `MAX_RAW_BYTES` (256 KiB, then `truncated`), are kept in memory only, keyed by the reply's `request_id`, for Turn details; a retry replaces its earlier record, nothing is written to disk, and they are gone when Bistre closes. Test: `raw_exchange::tests::records_are_bounded_and_a_retry_replaces_its_record`.
- No redirects on the provider client (`http_clients::provider_client`): a redirect response is an error. A cross-host redirect would otherwise carry `x-api-key` / `x-goog-api-key` (reqwest strips only `Authorization`) and, for 307/308, the request body. Update feeds and artifacts use a separate credential-free `ota_client` that follows at most 6 redirects, each to `https` or a loopback test host. Tests: `providers::tests::a_cross_host_redirect_never_forwards_the_key_or_the_body`, `http_clients::tests::ota_redirects_only_to_https_or_loopback`.
- Custom headers and body fields (`crates/bistre-core/src/custom_headers.rs`): parsed once into `CustomHeader`s, which only `parse_custom_headers` can build: a JSON object of string names to string values, at most 32, RFC 9110 token names, no reserved/credential/connection headers (`authorization`, `x-api-key`, `x-goog-api-key`, `api-key`, `cookie`, `host`, `content-type`, `accept`, `anthropic-version`, `anthropic-beta`, and the rest of that list), no control characters (a line break is refused as injection), printable ASCII after zero-width characters are removed, values ≤ 4 KiB. The body must be a JSON object (≤ 64 KiB). `save_provider_overrides` validates before saving and binds the headers to the provider origin; changing the base URL to another origin clears them (`diag.provider.headers_cleared`). An invalid stored entry stops the request before any reservation or send (`diag.provider.headers_invalid` / `diag.provider.body_invalid`), never a silent drop. Tests: `custom_headers::tests`, `egress_tests`.
- Pinned providers: a provider chosen by the chat or its assistant is used or the request fails with `diag.provider.pinned_unavailable` (turned off, removed, or no key); only the global default may fall back to the first configured provider. Test: `egress_tests::a_pinned_provider_that_is_off_never_falls_back_to_another`.
- Live voice and read aloud keys: keys rotate like other requests and a missing key fails closed. Gemini Live accepts an API key only as the `key` query parameter (an `x-goog-api-key` header is not accepted, Live API WebSocket guide), so that one URL carries the key: it is URL-encoded, the session is refused over plain `ws` to a non-loopback host (`live_insecure_transport`), and the URL is never logged. `OpenAI` Realtime keeps the base path and URL-encodes the model. Test: `voice::tests::live_targets_encode_secrets_and_refuse_insecure_public_hosts`.
- Multiple keys per provider (`crates/bistre-core/src/credentials.rs`): pasted text may hold several keys (one per line or comma separated, max 16), sanitized of `\r`, `\n`, zero-width characters, the BOM, and control characters, stored together in the OS `SecretVault`. Requests start at a process-wide round-robin index (`API_KEY_RR`) and fail over to the remaining keys immediately on 401 / 403 / 429 before any backoff (notice `key_failover_N_of_M`). The key hint reads `••••a1b2 (+2)`.
- Failure classification & hints (`crates/bistre-core/src/error_policy.rs`): `retry-after-ms` → `retry-after` (seconds or RFC 7231 IMF-fixdate) → Gemini `RetryInfo.retryDelay` (first 64 KiB of the body), at least 1 s; a zero `retry-after-ms` is no hint, so `retry-after` decides. There is no upper clamp: a hint longer than the retry budget left makes the run give up at once instead of retrying early into the same limit. Billing/credit stops, `PerDay` quota failures, and spend caps (`ProviderQuotaExhausted`) are never retried; transient-worded 400s are retryable. Typed keys drive jump-to-fix UI: `ProviderAuthFailed`, `ProviderRateLimited`, `ProviderQuotaExhausted`, `ProviderContextOverflow`.
- HTTP 400 heal ladder (`MAX_HTTP_400_HEALS = 6` resends, first applicable step wins, each raised as `ProviderRequestHealed` + detail code): strip Anthropic `thinking.display` → Gemini `thinkingLevel` → `thinkingBudget` → reasoning effort step-down (`max → xhigh → high`, `minimal → low`) → strip `stream_options` → toggle `max_completion_tokens` ↔ `max_tokens` → strip non-function built-in tools → strip `temperature`/`top_p` → drop reasoning. Gemini Interactions 400/404 still downgrades once to `streamGenerateContent`.
- Run-loop recovery (`execute_durable_stream_loop`): `ProviderContextOverflow` (413 or context-length markers) triggers one in-flight reversible compaction and a single retry; rate limits, transient `5xx`/408/409/425, connect failures, and streams that died before any output back off via `compute_backoff_wait_ms` within `retry_watchdog_max_wait_secs` (wall-clock since the first failure of the streak, so `Retry now` spends only the time that passed; jitter seeded per run, so runs that failed together do not retry together; one backoff per provider shared by every run, `provider_backoff.rs`, which `Retry now` clears; a 404 such as a wrong base URL is never retried), emitting `RunBackoffWaiting` (`retry_in_ms=…`). `EngineClient::retry_run_now` (and cancel) wake the wait instantly through a per-thread `tokio::sync::Notify`. Mid-stream retry never happens after partial output (no duplicated text or double billing): an idle timeout or body read error after any text or thinking returns the kept reply with `interrupted = true` instead of `ProviderStreamInterrupted`, gated by `error_policy::may_retry_stream` (test `a_stream_that_breaks_after_output_is_kept_not_retried`). A stream silent for 15 s when the app comes back (`SystemPowerEvent::AppResumed`, also on system wake) ends at once as interrupted instead of waiting out its idle timeout (test `a_stream_stalled_across_a_resume_ends_when_the_app_comes_back`); `app_resumed` never touches run journals. Stop takes effect within `CANCEL_POLL_INTERVAL` (50 ms) even while connecting or waiting for the first token: `dispatch()` and every chunk wait race `until_cancelled` (test `stop_interrupts_a_request_waiting_for_its_first_token`).
- History hygiene: replay sends only user/assistant/summary turns (UI interruption state lives in `provider_meta_json`, never in content); `compaction::enforce_role_alternation` merges consecutive same-role turns and drops assistant tails before dispatch; tool-call IDs are sanitized to `[A-Za-z0-9_-]{1,64}` and de-duplicated (`tools::sanitize_tool_call_id`).
- Deferred until native tool / reasoning replay lands (contract, not yet code): `tools` must serialize first in request bodies (enable `serde_json/preserve_order`), opaque signatures replay only for the same provider + model + dialect with a Franken-signature guard on Gemini chunks, cross-provider reasoning handoff is clipped to 8,000 chars (25% head / 75% tail), and historical tool outputs compact in quantized batches of 16.
- Property test: `chunk_boundaries_never_change_the_events` (`crates/bistre-core/src/sse.rs`, `proptest 1.12`, test-only dependency) checks that any split of an SSE byte stream yields the same events as the whole stream.

## Thinking Effort
`GenerationParams.reasoning_effort` is a typed `ReasoningEffort`: `ModelDefault`, `Off`, `Low`, `Medium`, `High`, `ExtraHigh`, or `Max`. It is parsed once from the `reasoning_effort` setting (`default`, `off`, `low`, `medium`, `high`, `xhigh`, `max`), and the default sends nothing. It reaches the wire only when the registry marks the model reasoning-capable (Spec 03); otherwise a model that cannot think would reject it with a 400 on every message. Field names below were verified against the live docs unless marked otherwise.

| Dialect | Field | Off | Low to Max |
|---|---|---|---|
| OpenAI Responses | `reasoning: {effort, summary: "auto"}` | `none` | `low`, `medium`, `high`, `xhigh`, `max` |
| OpenAI-compatible Chat | `reasoning_effort` | `none` | as above |
| Anthropic Messages | `thinking: {type: "adaptive", display: "summarized"}` + `output_config: {effort}` | `thinking: {type: "disabled"}` `[UNVERIFIED]` | `low` to `max` |
| Gemini Interactions | `generation_config: {thinking_level, thinking_summaries}` | `low` + summaries `none` | `low`, `medium`, `high`, `xhigh` (Max maps to `xhigh`) |
| Gemini generateContent (fallback) | `generationConfig.thinkingConfig: {includeThoughts, thinkingLevel}` `[UNVERIFIED]` | `LOW`, thoughts hidden | uppercase levels |

The 400 heal ladder covers each field:
- `StepDownReasoningEffort` steps `reasoning.effort`, `reasoning_effort`, `output_config.effort`, and `generation_config.thinking_level` down (`max`→`xhigh`→`high`).
- `DropReasoning` removes `reasoning`, `reasoning_effort`, `thinking`, `output_config`, `thinkingConfig`, `thinking_level`, and `thinking_summaries`.

Tests: `providers_tests::reasoning_effort_reaches_each_dialect_in_its_own_wire_field` and `error_policy::tests::effort_heals_cover_anthropic_and_gemini_interactions_fields`.

## 7. Media Input and Output (ADR-0019)
What a model reads and writes comes from the catalog (Spec 03), never from code. `crates/bistre-core/src/media_wire.rs` holds the wire shapes; `media_gen.rs` runs media-only turns.

- Route: a model that writes text answers in chat; a model that writes no text answers through its media API: video, else image, else speech (`MediaRoute::of`). Gemini image models answer in chat (Imagen is shut down); Anthropic writes no media. `OpenAI` Responses writes no audio, so a speaking model on the `OpenAI` dialect is sent to Chat Completions on the same host (`chat_wire_for`).
- Chat output: Chat Completions requests add `modalities` (`["image", "text"]`, `["audio", "text"]`) and, for audio, `audio: {voice, format: "pcm16"}` (the catalog's first voice, else `alloy`). Replies are read from `delta.images[].image_url.url` (data URLs) and `delta.audio` (`data` as 24 kHz 16-bit mono PCM, wrapped as one WAV; `transcript` is the reply text), Gemini `inlineData` parts (thought parts skipped), and Interactions `step.delta` media deltas `[UNVERIFIED]`. Gemini image models return pictures without a field asking for them `[UNVERIFIED]`. At most 16 files and 64 MiB per reply; more is left out with a log line.
- Format settings: one choice for every chat in `settings.media_options` (`{aspect_ratio, resolution, duration_s}`, set from the composer's Format chip). `MediaPick::for_model` keeps only the values the model's catalog entry lists (Spec 03), so a value chosen for one model never reaches another that does not list it, and no setting sends no field. Fields: OpenRouter `/images` `aspect_ratio`, `resolution`; `/videos` `aspect_ratio`, `resolution`, `duration` (seconds); the task API `ratio`, `resolution`, `duration`; OpenRouter chat `image_config.{aspect_ratio, image_size}` `[UNVERIFIED]`; Gemini Interactions `response_format: {type: "image", aspect_ratio, image_size}` (checked against the official docs: the reply keeps its text) and `generateContent` `generationConfig.imageConfig.{aspectRatio, imageSize}` `[UNVERIFIED]`; Gemini video `response_format.{aspect_ratio, resolution, duration: "<n>s"}` `[UNVERIFIED]`.
- Later turns: `media_wire::carry_generated_media` sends each reply's generated files with the next user message, for the kinds the model reads, so a chat model can edit a picture it drew; a reply with files and no text is replayed as `[Generated files: <names>]`, since several providers reject an empty assistant turn. Gemini: each `inlineData` part's `thoughtSignature` is kept in order (`ReasoningBlock::GeminiPictureSignatures`, empty for an unsigned part); when the target may replay the reply's reasoning, every picture has a signature, and the reply is among the turns whose images are kept, its pictures go back as its own parts after the text, each with its signature, and the next user message leaves them out (`wire_history_gemini::own_pictures`); otherwise they ride on the user message as above. Google's live docs describe no signature on picture parts, so the replayed shape follows the stream and is `[UNVERIFIED]` against a live key.
- Images: `POST {base}/images` with `input_references` on OpenRouter `[UNVERIFIED]` shape, else `POST {base}/images/generations` (`model`, `prompt`, `n: 1`); `data[]` carries `b64_json` or `url`.
- Video jobs: `POST {base}/videos` (`frame_images` for a first frame) polled at `GET /videos/{id}` (OpenRouter `pending`, `in_progress`, `completed` with `unsigned_urls`, `usage.cost`; `failed`, `cancelled`, `expired` with `error`), else `POST {base}/contents/generations/tasks` (`content[]` text and `image_url` with `role: first_frame`) polled at `GET /contents/generations/tasks/{id}` (`succeeded` with `content.video_url`). OpenRouter is asked on `/videos` only; another `OpenAI`-shaped provider that answers 404 or 405 there is asked on the task API. Every 5 s for at most 30 min; a job a stop or restart cut off is kept for Try again (ADR-0019 Decision 9). Gemini: `POST /v1beta/interactions` with `response_format: {type: "video"}`, the file in `steps[].content[]` (`data` or `uri`), thought steps skipped.
- Speech: `voice::synthesize_speech` (Gemini `generateContent` with `responseModalities: ["AUDIO"]`; `/audio/speech` elsewhere). OpenRouter is asked for `pcm` and the bytes are wrapped as 24 kHz WAV `[UNVERIFIED]` rate (its `wav` serves Gemini voices only). No voice chosen: the catalog's first voice for the model, else the dialect's own default.
- Inputs: the latest user message is the prompt; its pictures go along when the model reads images, else the latest reply's pictures (so "make it bluer" edits the last one). In chat, Chat Completions sends `input_audio` (`wav`, `mp3`; OpenRouter also `ogg`, `flac`, `aac`, `m4a`, `aiff`) and OpenRouter `video_url` data URLs when the catalog says the model reads them; anything else stays a named note.
- Files: stored as content-addressed attachments (`attachments::store_attachment_bytes`) named by their hash, typed by their bytes (`mime_sniff`: PNG, JPEG, GIF, WebP, WAV, MP3, Ogg, FLAC, MP4, WebM), on the assistant reply's `attachments`. A URL on the provider's own host is fetched with its key; any other URL through `PublicWebTransport` with none. Downloads are bounded by the same 64 MiB.
- Spending: Spec 06 "Media". Tests: `media_wire::tests` (format settings per wire, carried files), `request_body::tests::picture_settings_reach_chat_requests_for_models_that_draw`, `media_gen::tests`, `mime_sniff::tests`, `wire_history` `compat_media_part` through `media_gen::tests::a_chat_reply_keeps_the_pictures_it_streamed`.
