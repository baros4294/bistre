# Spec 04 — Native Agent Harness, In-Process Tools & MCP

## 1. Zero-Fork In-Process Rust Tools
Every core workspace tool runs in-process inside `crates/bistre-core` (zero shell fork overhead, deterministic cross-platform UTF-8 handling):
- `read`: Line-ranged UTF-8 file reader returning `blake3` line-range hashes (`LINE#HASH`) and enforcing binary/size guards.
- `grep`: Built directly on `grep-searcher 0.1.17` + `ignore` (ripgrep engine) honoring `.gitignore` with bounded match/byte caps.
- `glob`: Built on `globset` + `ignore`, returning deterministic mtime-sorted paths.
- `edit`: Capability-scoped via `cap-std 4.0.3` `Dir` (`openat2`/`O_NOFOLLOW` eliminating symlink/TOCTOU escapes), verifying exact `blake3` hash anchors prior to atomic temp-file + `rename` swap (with 3-step backoff on Windows AV `ERROR_SHARING_VIOLATION`) and persisting a pre-image snapshot for 1-tap rewind.
- `diff`: Unified structured diffs computed in-process via `imara-diff`.
- `shell` (guarded): every child process (tools, hooks, git worktrees) is created only through `process_util::no_window_command` (Windows `CREATE_NO_WINDOW`, Unix own process group, null stdin, scrubbed provider keys; raw `Command::new` is banned by `just guard` and `clippy.toml` `disallowed-methods`). The Windows shell prefers `pwsh -NoLogo -NoProfile -NonInteractive -OutputFormat Text` (fallback `cmd /C`) with `#< CLIXML` stderr decoded to plain text and `PYTHONUNBUFFERED=1`; a timeout kills the whole tree (`taskkill /T /F` or a process-group `SIGKILL`). Lifetime containment (`ADR-0010`): Windows children each join their own kill-on-close Job Object through `process_util::spawn_contained`, and Linux/Android children get `PR_SET_PDEATHSIG(SIGKILL)` (audited shim in `bistre_crypto::containment`), so a crashed Bistre never leaves tool, hook, or git-worktree children running. On timeout `run_bounded` walks the live tree before terminating the job and reaping the root; captured stdout/stderr are capped at 32 MiB each. Git worktree calls go through `run_bounded` with a 120 s bound.

## 2. Isolated Worktree Sub-Agents, Skills, Hooks & Scheduled Cron Automations
- Sub-agents isolate mutations via guarded `git worktree add --detach` (`crates/bistre-core/src/subagents.rs`), falling back cleanly to a copy-sandbox (skipping `.env` and secret files) when `git` CLI is absent or on Android, returning typed `SubagentProgressReceipt` outputs.
- **Progressive `SKILL.md` Discovery & `AGENTS.md`** (`crates/bistre-core/src/skills.rs`): Indexes YAML frontmatter (`name`, `description`) at workspace bind time with zero prompt bloat and loads full skill bodies on demand within workspace boundaries.
- **Local Workspace Lifecycle Hooks** (`crates/bistre-core/src/hooks.rs`): Executes configured `.bistre/hooks.json` hooks (`PreToolUse`, `PostToolUse`, `RunFinished`, `RunFailed`) through `run_bounded` with hard timeouts (1-60 s) and stripped provider API keys. Hooks run only after the user approves them in Settings > Agent: the approval stores the `blake3` digest of the exact file (`agent.hooks_approved:<root hash>`), so any edit needs a new approval, and `approve_workspace_hooks` refuses a digest that no longer matches the file (`hooks_changed`). An unapproved, failing (non-zero exit), or unrunnable pre-tool hook blocks the call with an error tool result and `diag.hooks.approval_required` (unapproved); post-tool hook failures are logged. Hooks race the run's cancel signal. The file is capped at 64 KiB; an unreadable or malformed file is an error. Tests: `hooks::tests`, `approval_flow_tests::pre_tool_hooks_need_approval_and_a_failing_one_blocks_the_call`, `apps/bistre_app/test/workspace_hooks_test.dart`.
- **Fail-closed tool policy**: an unreadable `agent.tool_permissions` map (storage error or not a JSON object) blocks every tool except Tier-0 reads and hides the write tools (`ActiveToolCatalog.policy_unreadable`). Tool arguments that are not a JSON object are an error tool result with no permit (an empty string means no arguments), never an empty `{}` call. Tests: `approval_flow_tests::an_unreadable_permission_map_blocks_everything_but_reads`, `malformed_tool_arguments_are_an_error_not_an_empty_call`.
- **Live shell output** (P21, `shell_progress.rs`): a running `shell` call streams its output to the tool row as `ToolExecutionUpdated { status: "running" }`, at most one event per 250 ms carrying the last 16 KiB; a slow reader loses progress copies, never captured output (`process_util::run_bounded_with_progress`). Tests: `output_arrives_while_the_command_still_runs`, `progress_is_coalesced_and_bounded`.
- **Read-only Plan mode** (opencode #65442): Plan mode hides write tools and is also enforced where tools run: every call that is not a Tier-0 read (edit, shell, MCP, or a tool the model calls anyway) gets an error result "Refused: this chat is in read-only Plan mode" without asking or running (`ActiveToolCatalog::read_only`). Test: `approval_flow_tests::plan_mode_refuses_every_write_even_when_the_model_calls_one`.
- **Step limit** (R18): a run that reaches `MAX_RUN_STEPS` (24) while the model still wants to go on (tool calls pending, tools just ran, or a paused turn) ends as failed with `diag.run.step_limit_reached`, never as a silent "complete". Test: `egress_tests::a_run_stopped_by_the_step_limit_says_so`.
- **Scheduled Cron & Interval Automations** (`crates/bistre-core/src/cron.rs`): interval (`every 30s/15m/2h/1d`) and full 5-field UTC cron (`*`, `*/N`, values, ranges, stepped ranges and lists in every field; day of month and day of week combine with OR as in standard cron; searched up to four years ahead so Feb 29 is found). A bad schedule turns its job off with `last_status = invalid_schedule` and never fires (it became "every hour"). A due job starts its real run (`cron::start_job_run`: a new chat named after the job, with its assistant and mode, sent its prompt; `last_run_id` records it); approvals in that run wait in its chat (`PauseAndNotify`). The daemon's housekeeping sleeps 1 s to 5 min until the next deadline and wakes only on run start, end and state changes, never on streaming deltas. Tests: `cron::tests::all_five_cron_fields_are_honoured`, `a_bad_schedule_turns_its_job_off`, `egress_tests::a_due_scheduled_job_starts_a_run_with_its_prompt`, daemon `housekeeping_tests`. Open: `DenyTier2AndContinue` / `SandboxWorktreeAuto` policies and `use_worktree` are not applied to scheduled runs yet.
- **Sleep-Immune Durable Runs & Mid-Stream Steering (`ADR-0013`)**: Every agent run and step journals to SQLite WAL (`agent_runs`, `run_steps`, `steering_queue`) behind OS sleep leases (`PowerCoordinator` / Win32 `PowerCreateRequest` / Linux `systemd-inhibit` / Android `BistreAgentService` `specialUse` FGS + optional `TermuxBridge`). Mid-stream user steering messages inject cleanly at step boundaries without cancelling active generations.

## 3. MCP Client (Streamable HTTP, Spec `2026-07-28` + Legacy Fallback)
- Bistre's own Streamable HTTP client (no SDK, `ADR-0018`) targets **`2026-07-28`** as primary (`server/discover`, stateless `_meta` capabilities, `Mcp-Method`/`Mcp-Name` headers, `ttlMs`/`cacheScope` tool caching, `subscriptions/listen`, MRTR `resultType: "input_required"`, `io.modelcontextprotocol/tasks` extension).
- Auto-negotiates seamless fallback to `2025-11-25` / `2025-03-26` handshake when `server/discover` is unsupported.
- Explicitly omits deprecated MCP features (Roots, Sampling, Logging, HTTP+SSE, OAuth DCR).
- **MCP over stdio** (`crates/bistre-core/src/mcp_stdio.rs`, checked against the MCP 2025-11-25 and 2026-07-28 specs on 2026-11-26): ONE long-lived session (process) per server, reused by every call (R15; 2026-07-28 stdio: clients "SHOULD NOT use an individual task, thread, or conversation as the lifetime boundary"), so ordinary use never spends the `3 starts / 10 min` restart budget. The child is held for the session's life (the command sets `kill_on_drop`; the old code dropped it at spawn, killing every server at once). A broken session (crash, timeout, endless line) is dropped, killing its tree, and the next call starts a new one; a crashed call is never resent. A command/args change starts a new session after closing the old one; saving the server list closes every session (and resets the restart budgets), and so does engine shutdown (child pipe reads run on the blocking pool, so an open session would also block runtime shutdown). Stdout lines are read bounded at `MAX_STDIO_LINE_BYTES` (1 MiB, R16). A message with a `method` is the server's request or notification, never our response even when it reuses our id (R43): `ping` gets `{}`, anything not negotiated (e.g. `roots/list`) gets `-32601`. JSON-RPC errors on stdio and HTTP alike become errors carrying the code and the server's message (`mcp::json_rpc_result`, R17). Tests: `mcp_stdio_tests.rs` (the test binary re-runs itself as a mock server: `calls_share_one_session_per_server`, `server_requests_are_answered_not_taken_as_responses`, `a_broken_session_is_killed_and_replaced`, `a_crashed_server_is_restarted_for_the_next_call`), `mcp::tests::an_http_json_rpc_error_is_an_error_not_a_result`.
- **Noisy Server Resilience** (the stdio transport keeps the 64 KiB `stderr` ring and non-JSON `stdout` quarantine): caps per-tool result payloads at `256 KiB` (spilling overflow to local artifacts) and sorts exposed tool schemas deterministically for LLM prompt-cache stability.

## 4. Harness Precision & Web Safety
- **Stale-read guard** (`tools::ReadLedger`): every `read` records the file digest per scope (thread); an `edit` after the file changed on disk fails with `DiagnosticKey::ToolStaleRead`. Failed edits return a near-miss hint (`target_not_found;near_line=N`); CRLF files keep CRLF when the model sends LF text; partial reads end with a footer telling the model never to rewrite a whole file from a truncated view.
- **One dispatch gate** (`crates/bistre-core/src/approval.rs`): each approved call becomes a one-use, non-`Clone`, non-serializable `ToolExecutionPermit` bound to `(thread, tool, arguments digest, policy revision)` and claimed with an atomic compare-exchange; `save_settings` calls `invalidate()` synchronously. Approval is a separate step: `approve_tool_call(thread, tool, arguments)` (called when the user approves) stores the permit for `60 s` (at most `64` outstanding) and returns its id; `execute_workspace_tool(..., permit_id)` removes it and claims it against the exact arguments. Only Tier-0 read-only calls are auto-issued, by core policy, never by the caller. Tier-3 calls fail with `diag.tool.tier_blocked`. Tests: `approval.rs` and `non_read_only_tools_require_an_exact_user_approval` in `crates/bistre-core/src/tests.rs`. `RunActivity` times steps on a monotonic clock that ignores gaps `> 5 s` (sleep).
- **Live approvals in a run** (`crates/bistre-core/src/agent_tools.rs`): a paused call emits `ToolApprovalRequested { thread_id, run_id, call_id, .. }` and waits in `PendingApprovalMap` under `ApprovalKey { thread_id, run_id, call_id }`; `respond_tool_approval(thread_id, run_id, call_id, decision)` releases exactly that waiter, so two chats paused on the same provider id (an empty id becomes `call_0`) never release each other. Decisions: `approve_once`, `approve_for_thread` (an `ApprovalMemory` chat grant for the exact tool + canonical-argument digest; any arguments only for Tier-0 reads), `deny` (the identical call is refused for the rest of the run without asking: "already denied"), and `stop` (refuse and cancel the run). Memory is bounded at `1,024` entries, run denials are forgotten when the run ends, chat grants when the chat is deleted. The wait has no time limit and does not poll: only the decision, the run's cancel signal (via its `wake` `Notify`), or a dropped responder (deny) ends it, and `PowerCoordinator::pause_for_user` gives back the keep-awake lease while waiting. Tests: `agent_tools::approval_flow_tests`, `apps/bistre_app/test/approval_flow_test.dart`.
- **`PublicWebTransport`** (`crates/bistre-core/src/ssrf.rs`): `web_fetch` and the pricing registry use a dedicated client with public-IP pinning at connect time (custom DNS resolver), `.no_proxy()`, `Policy::none()` plus `<= 6` manually re-validated redirects, full IANA IPv4/IPv6 special-purpose exclusions (CGNAT, ULA, documentation, 6to4/Teredo, NAT64 and IPv4-mapped unwrapping), `*.localhost` / scoped `%zone` / embedded-credential rejection, a `2 MiB` streamed body cap, and fail-closed construction.
- **MCP over HTTP** (`mcp::McpHttpTransport`): loopback servers use a dedicated no-proxy, no-redirect client; every other host goes through `PublicWebTransport` (private LAN hosts are refused). `Mcp-Session-Id` is tracked and an HTTP `404` on an existing session renews it exactly once. A tool call negotiates first (MCP `2026-07-28` stateless `server/discover`, else a `2025-11-25` `initialize` session), so `tools/call` is sent exactly once: any other failure, a `400` included, is an error and is never resent (it may already have run). A `2025-11-25` session is closed with `DELETE` after the call (A-S9; test `mcp::tests::a_failed_tool_call_is_never_resent_and_the_session_is_closed`). Per-call timeout `60 s`, responses capped at `1 MiB` before the `256 KiB` render cap. Contract for the future stdio transport: `3 starts / 10 min` restart budget that never resends the call that discovered the crash, stable `mcp__<server>__<tool>` names (`<= 64` chars), bearer tokens only over HTTPS or loopback, and a deferred `mcp_schema` tool once more than 6 MCP tools are exposed to a model.
- **Skills**: discovery indexes at most `64` `SKILL.md` files and skips files above `512 KiB` without reading them; skill and `AGENTS.md` bodies are read raw (never through the line-numbered `read` tool).

## Context accounting (W3.E, R26)
- Tool schemas count schema by schema (`ActiveToolCatalog::schema_tokens`); the breakdown's Built-in and MCP rows add up to exactly what a run counts (`context_breakdown::tests::tool_rows_sum_to_the_tokens_a_run_sends`). Deferred MCP schemas (behind `mcp_schema` past 6 tools) are listed as not sent and never added to the total.
- The history estimate includes what replay sends besides text: tool calls (name and arguments) and reasoning blocks (R26, `compaction::tests::tool_arguments_and_reasoning_are_counted`); the proactive shorten before a request adds the tool schemas and keeps `AUTO_COMPACT_RESERVE_PERCENT` (15 %) of the window free.
