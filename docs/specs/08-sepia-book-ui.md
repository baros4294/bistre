# Spec 08: Custom Sepia Book UI (Pure `package:flutter/widgets.dart`)

## 1. Zero UI Libraries & Mechanical Enforcement
`apps/bistre_app` imports only `package:flutter/widgets.dart` (plus `foundation`, `rendering`, `services`, `painting`). Importing `package:flutter/material.dart`, `package:flutter/cupertino.dart`, `package:material_ui`, `package:cupertino_ui`, `package:flutter_localizations`, `package:google_fonts`, third-party state frameworks, or direct HTTP/SQL libraries is a compile-time static analysis error enforced by `tools/bistre_lints` (`bistre_forbid_ui_kits`), alongside `bistre_forbid_hardcoded_ui_strings`, `bistre_forbid_layout_animations`, `bistre_forbid_raw_colors`, and `bistre_forbid_non_directional_geometry`. The layout-animation rule also rejects `SizeTransition`, `AnimatedCrossFade`, `AnimatedDefaultTextStyle`, and `AnimatedFractionallySizedBox`; the directional rule also rejects `Positioned(left:/right:)` and `TextAlign.left/right`. `just i18n-check` rejects internal or literary jargon in every locale and enforces the `design.md` §9 plain-language glossary in English. Visual tokens, typography, and the 10 Ink Primitives are governed exclusively by [`docs/design/design.md`](../design/design.md).

## 2. Pure-Widgets Ergonomics & Cross-Platform Controls
- Root Shell: `WidgetsApp` configured with explicit `color`, `textStyle`, `localizationsDelegates`, `locale`, `supportedLocales`, `builder` injecting `BistreTheme` + `BistreLocalizations` + `Directionality`.
- Selection & Cross-Span LaTeX Copy: Wrap thread feeds in `SelectableRegion` with custom `BistreSelectionControls` (copy / select all toolbar rendered via `FolioOverlay` / `OverlayPortal`, zero Material toolbar). `LineSelection` (`apps/bistre_app/lib/design/line_selection.dart`) copies text spread over separate widgets (paragraphs, list items, code rows) with a line break between them, and a math block copies its LaTeX source with its own Copy LaTeX button (`math_folio_view.dart`).
- IME Composition Safety: `QuillInput` wraps `EditableText` directly, never modifies `controller.text` while `controller.value.composing.isValid` (protecting Vietnamese Telex/VNI and CJK IME composition), never sets `enableSuggestions: false` on prose inputs, and uses `Characters` grapheme indexing.
- Live-Stream Scroll & Leaf Streaming: the feed is a full-width `CustomScrollView` whose items each center a `ConstrainedBox(maxWidth: readingWidth)` (`_ReadingColumn`), so the mouse wheel scrolls from the empty page margins; a chat opens anchored at its newest message; `UserScrollNotification` unpins auto-follow on manual upward scroll and re-pins within 24px of the tail. Stream deltas update only `LiveTurnNotifier` (`apps/bistre_app/lib/features/shell/live_turn_notifier.dart`), read by the single streaming item through a `ValueListenableBuilder` inside a `RepaintBoundary`; `FolioController` (shell, header, sidebar) is not notified per delta (regression-tested in `apps/bistre_app/test/anti_pattern_regression_test.dart`).
- Code Fences & Inline SVG Preview: soft-wrap follows `AppSettings.code_wrap_mode` (`auto` wraps below 640 px, `on`, `off`) with a per-fence toggle kept in `CodeWrapScope` so it survives virtualization. Fences render as independent `kCodeChunkLines` (8-line) chunks, each a highlighted `Text.rich` behind its own `RepaintBoundary`; while a reply streams, finished chunks keep the identical widget instance, so only the growing tail chunk is re-highlighted, laid out, and repainted. Highlighting runs per chunk, so a block comment or string spanning a chunk boundary is tinted per chunk (the source text, selection, and copy stay exact). `MarkdownFolioView` keeps up to four open-fence parse memos (`apps/bistre_app/test/streaming_markdown_test.dart`). Fenced `svg` blocks also offer an offline `Preview` / `Source` toggle backed by a safe pure-Dart vector painter (zero scripts or network fetches; `svg_preview_painter.dart`): `rect`, `circle`, `ellipse`, `line`, `polygon`, `polyline`, and `path` (every path command, absolute and relative, implicit repeats, compact arc flags, `fill-rule`), at most 128 shapes and `kMaxSvgPathNumbers` numbers per path; a malformed token ends the path and what came before still draws. Test: `svg_path_test.dart`.
- Android 15/16 Edge-to-Edge: `MainActivity.kt` invokes `WindowCompat.setDecorFitsSystemWindows(window, false)`; `BistreScaffold` maps physical `MediaQuery.paddingOf(context)` left/right cutouts according to `Directionality.of(context)` (preventing RTL cutout inversion) and computes bottom avoidance via `max(MediaQuery.paddingOf(context).bottom, MediaQuery.viewInsetsOf(context).bottom)` so bottom chrome never jumps when floating/docked keyboards open.
- State Management: Built-in `ChangeNotifier` / `ValueNotifier` + `InheritedNotifier` + `ListenableBuilder` only (zero third-party state frameworks). The root `WidgetsApp` listens only to `FolioController.appearance` (an `AppAppearance` value: theme, accent, typography, reduced effects) and the locale, and reuses the resolved theme until that value changes; the window title follows the controller through a listener. Toasts, search (query, scope, results), the Draft saved label, and the sidebar filter each have their own notifier read only by the widget that shows them, so none of them rebuilds the shell; the engine's draft-saved echo changes nothing and notifies nothing. Thread switches carry a generation number and search carries a sequence number (150 ms debounce), so a slower, older response never replaces newer state. Chats still inside their Undo window are deleted when the app pauses or closes. Drafts: the composer saves its draft on every change to its text, typed or not (a clear after Send, a `/` command, an inserted skill), 220 ms after the last change, so a sent message or command never comes back as the draft; a draft still waiting is saved at once when the app goes inactive, hidden, or paused, when the composer goes away, and at shutdown. While the `/` or `@` menu is open, Enter picks the highlighted entry and never sends the typed command to the model. The Chat parameters drawer keeps each chat's unconfirmed prompt and model edits until that chat stores them, so switching chats during a slow save never shows (or later saves) an older value. A message with an open inline edit stays alive when scrolled out of view, so the half-written text survives. Tests: `draft_persistence_test.dart`, `inspector_prompt_test.dart`, `inline_edit_keepalive_test.dart`. Sidebar (3a/3b): `SidebarDock` lays the chat area out once per toggle and only moves it while the sidebar slides (180 ms ease-out-cubic, no fade, sidebar kept mounted while closed); one sidebar toggle in the chat header; Settings stays in the header. Test: `sidebar_dock_test.dart` (the chat area takes exactly two widths across a toggle, LTR and RTL). Context breakdown: core's `ContextBreakdown` (closed `ContextCategoryKind` rows, limit, reserve, per-server MCP tools; FFI `context_breakdown`, replacing `context_usage`) drives the ring and its two-page popover (`context_breakdown_test.dart`). Provider fields: placeholders and the server URL of a new provider come from core's dialect descriptor (`provider_fields_test.dart`); custom headers and body fields are edited only in Advanced (one Save; core validates them); Advanced shows where requests go and labels the API formats from the catalog; a failed connection test names the URL tried (`provider_test_connection_test.dart`). The model field is one combobox: focus opens the provider's models (fetched once if none), typing filters, arrows move, Enter picks the highlighted model or keeps a typed id, Esc or a click elsewhere closes (`model_combobox_test.dart`); the chat parameters drawer uses the same field. Studio and sources: the header always shows the Studio button (`studio_header_test.dart`); Chat notes were removed (their `thread_notes:<id>` KV rows stay untouched); the Studio `Sources` tab and Turn details list the web pages a reply used, from core's typed grounding (title, site, cited passage, Open in browser, Copy link; `BistreDesktopHost.openWebLink` hands only an `http(s)` link with a host and no login to the Windows runner's `ShellExecuteW`, Android's browsable `ACTION_VIEW`, or core's `xdg-open`, and a notice says when no browser opened it), never URLs scraped from text in Dart (`grounding_sources_test.dart`). Input and keyboard: one-line fields submit on Enter, fields are named for screen readers, the context menu follows the clipboard (`quill_input_test.dart`); chat titles rename in place via `InlineTitleEditor` (`title_rename_test.dart`); Esc stops a reply only from the empty composer, `Ctrl+.` from anywhere (`escape_stop_test.dart`); IME compositions own their keys and deferred edits run when they end (`ime_composing_test.dart`); auto-follow resumes only on idle-near-bottom or Jump to latest (`auto_follow_test.dart`); modals trap and restore focus (`modal_focus_test.dart`). Committed markdown is parsed once per text (256-entry LRU in `MarkdownFolioView`), and messages never replay an entrance animation. Tests: `apps/bistre_app/test/anti_pattern_regression_test.dart`.
- Plain Everyday Copy & Vertical-First Restraint: User-facing strings across `en`, `vi`, and `ar` strictly use everyday language (`Send`, `New chat`, `Recent`, `Pinned`, `You`, `Light`/`Dark`, `Document`/`Bubbles`, `Settings`, `Providers & Keys`). Navigation, providers, assistants, topics, chats, and settings compose from clean vertical lists, reserving horizontal segmented tracks strictly for 2–4 compact mutually exclusive toggles.
- Windows 11 Native Desktop Host (`apps/bistre_app/windows/runner/`): Uses a true native Win32 frame (`Bistre`) with DWM Sepia titlebar tinting (`DWMWA_CAPTION_COLOR`, `DWMWA_TEXT_COLOR`, `DWMWA_BORDER_COLOR`, `DWMWA_USE_IMMERSIVE_DARK_MODE`, `DWMWCP_ROUND`), `WS_CLIPCHILDREN | WS_CLIPSIBLINGS` composition hygiene (no `CS_HREDRAW | CS_VREDRAW`, `SWP_NOREDRAW` resize without GDI erase flicker after first visible frame), Impeller renderer default (owner decision, `BISTRE_IMPELLER=off` falls back to Skia GLES, the Linux runner does the same through `fl_dart_project_set_enable_impeller`), deferred first-frame reveal + `ForceRedraw()` after visible (zero blank launch/maximize frames), live `onWindowBoundsChanged` multi-monitor persistence (skipping redundant bounds calls), `720×520` minimum window dimensions, and a native `MethodChannel('bistre/desktop_host')` for OS file/folder pickers (`IFileOpenDialog`/`IFileSaveDialog`), `ShellExecuteW` folder opening, `Shell_NotifyIconW` system tray & completion notifications (with the tray off, the icon shown for a notification goes when its balloon closes; with it on, closing the window hides Bistre to the tray, whose right-click menu offers Open Bistre and Quit, labelled by the app via `setTrayLabels`; the tray and run-at-startup are re-applied at each launch), `HKCU` auto-start, queued WAV playback on `waveOut` (streamed live-voice chunks play in order; Stop clears the queue), the system voice for read aloud through SAPI (`ISpVoice`), and one-phrase dictation through SAPI recognition on a worker thread (default microphone, 12 s limit, stoppable); neither starts a child process. A Windows accent-colour change keeps the app's own caption colours.

## 3. Interaction Craft & Surfaces
- One bold mark: `rubricMark` / `kRubricMarkWidth` (`apps/bistre_app/lib/design/bistre_decorations.dart`) on the selected sidebar chat, active settings category, and empty-chat intro.
- Recovery surfaces: composer backoff notice with countdown and inline `Retry now` (`EngineClient::retry_run_now`); jump-to-fix chips for key/quota, conversation-limit (`Shorten the conversation`), and spending-limit errors; a reply a restart cut off (`diag.run.interrupted`) shows on its chat with `Try again` until it is retried or dismissed, and the fix drops below the sentence when both do not fit (`composer_notice.dart`); chat delete with an 8 s `Undo` toast (no confirmation step); instant non-destructive reply regeneration with an 8 s non-blocking toast (`Previous`) that cancels and restores the prior sibling branch in one click.
- Large text: `textScaledWidth` (≤ 1.6x) sidebar and settings-nav widths; `BistreSettingRow` lays out through `LabelControlLayout` (`apps/bistre_app/lib/design/label_control_layout.dart`), which keeps the control beside the label when the label's width (capped at 120 px × text scale) plus the control fits and stacks it below otherwise; icons scale with text up to 1.5x (`iconScaleOf`); popovers stay inside the window (`PopoverPlacement`); a reply's header uses the same layout, so its actions drop below the name and wrap when needed; header actions stack (wrapping) when width ÷ text scale < 600 px at ≥ 135% text; the composer toolbar is measured, not guessed (see Composer below); segmented controls shrink with ellipsis instead of overflowing. Gallery: `ui_gallery_matrix_test.dart` (`*-200-*` captures) and `ui_gallery_stress_test.dart` (`*-phone-200`).
- Context gauge: `ContextGaugeRing` (`apps/bistre_app/lib/features/chat/context_gauge_ring.dart`) shows core's offline BPE count (`EngineClient::context_breakdown`, `crates/bistre-core/src/tokenizer.rs` via `tiktoken 5.1.1` universal `o200k_base`) of what the next request sends for the visible branch: the system prompt, the Write-mode story prompt, and the history, with the same projection a run uses, so a compaction or context pin lowers it. `FolioController.contextBreakdown` asks again when the chat, the branch's newest node, or the pin changes, and a sequence number drops older answers. Only the gauge listens. Tapping the ring (or Enter/Space) opens the breakdown popover: session spend (`Session $X`), stacked bar, rows for instructions, story notes and cards, chat history (with message count), unsent draft (core recounts on open), attached files count, and free space, plus Shorten the conversation and Prices.
- Per-turn usage details pill: `UsageDetailsPill` (`apps/bistre_app/lib/features/chat/usage_details_pill.dart`) makes each assistant reply's token/cost footer interactive: hover hint on pointer rest, and tap/Enter/Space opens a breakdown card with model, provider, input tokens, cached read/write tokens, reasoning tokens, output tokens, TTFT, duration, output speed (`tok/s`), and cost (or unavailable-cost status). The footer reads `↑in ↓out cost` (`chat.tokens_meta_cost`, spoken as words via `chat.tokens_spoken_cost`); on desktop the card opens after 500 ms of hover and closes 150 ms after the pointer leaves unless pinned by a tap. `UsageBreakdownRows` is shared with Turn details, which shows the plain summary first and folds raw metadata.
- Tab switcher & cross-provider model picker: `TabSwitcherModal` (`apps/bistre_app/lib/features/shell/tab_switcher_modal.dart`) opens from desktop `ChatTabStrip`'s overview icon button (its hint names `N tabs`) or phone header's compact tab badge, with 1-col/2-col responsive grid, filter above 3 tabs, `Close N empty` bulk cleanup, `StreamingPulseDot` on streaming tabs, `Ctrl+Tab`/`Ctrl+Shift+Tab` cycling, and Android back dismissal. `ModelPickerPopover` (`apps/bistre_app/lib/features/shell/model_picker_popover.dart`) unifies all providers with search (`Enter` picks top match), provider filter chips, slash-prefixed family filter chips, active-model pinning, and badges only for exceptions (`On device`, `Stored`, and the provider name when its icon cannot show it); chips carry no counts.
- Profile name & avatar: Settings > Appearance > Profile holds `AppSettings.user_display_name` (which labels user messages and injects `"The user's name is <name>."` into non-Write system prompts via `engine_runs::with_user_name`) and an optional local profile picture picker (`UserAvatarThumb`), rendered with bounded `ResizeImage` decoding (zero synchronous `existsSync()` on the UI thread) in Settings, user message headers, and the sidebar footer. Settings > Appearance > Display also exposes an opt-in `Show message times` toggle (`showUserTimestamp`, default off). Inline `$...$` math rendering in `MarkdownFolioView` guards against currency strings (`$10 to $20`) so prices remain plain text while genuine TeX expressions still render. Tests: `apps/bistre_app/test/profile_avatar_and_math_test.dart`.
- Composer tools & thinking: `ComposerToolsControl` (`features/chat/composer_tools_control.dart`) opens an above-anchor popover showing Mode (`Chat`/`Plan`/`Build`/`Write`), 4 Tool permission presets (`Off`/`Strict`/`Balanced`/`Sandbox`), native folder picker, web search toggle (DuckDuckGo default), and optional assistant reply start (prefill). `ThinkingControl` (`features/chat/thinking_control.dart`) opens the shared `ThinkingEffortPicker` (also in the chat inspector and provider settings): `Auto` and `Adaptive` chips, then a `BistreSlider` over Off–Max that is `unset` (hollow thumb, no fill, the choice as its spoken value) while Auto or Adaptive is chosen. The slider spans only the levels the active model's catalog entry lists (`EngineModelCatalogInfo.effortLevels`, every level when it lists none); a model with one level shows it as a chip instead (Spec 02). There is no free-text effort: core buckets any text into the same levels. `MediaOptionsControl` (`features/chat/media_options_control.dart`), the `Format: 16:9 · 2K` chip, shows beside Thinking when the model's catalog entry lists format choices (Spec 03); Thinking hides for a model that writes no text or reports no reasoning, and an unknown model keeps Thinking. Its popover has a group per listed kind (Shape, Size, Length), each opening with Default (the provider decides); shape chips carry a frame drawn at the true proportions. A saved value this model does not list shows as Default and is not sent. Saving a level is quiet (the chip shows it). On phones (< 720 px) the composer is one row (`composer_phone_controls.dart`: `ComposerTrayToggle` + `ComposerSendActions`) with the toolbar in a `+` tray.
- Chat overlays: `PinnedRepliesModal`, `TurnDetailsModal` (web citation links + raw metadata JSON), and `AttachmentViewerModal` (`features/chat/chat_overlays.dart`) trap focus and dismiss cleanly via Escape or Android back. Sent pictures show in the message as 96 dp thumbnails (`SentPictureThumb`, decoded at most 288 px a side; an unreadable file shows an icon) that open the viewer; other files are chips. The file viewer zooms pictures, shows text and code (`isViewerText`: `text/*`, JSON, XML, YAML, TOML, JavaScript, shell, SQL) as selectable text with Copy, at most `kMaxViewerTextBytes` (256 KiB) with a note when cut, and otherwise names the file. Its action row holds only what the platform and file allow: Play and Stop for WAV on Windows and Android (`playWavBytes`, at most 64 MiB; closing the viewer stops it), Copy picture for a picture other than SVG (Windows `CF_DIBV5` plus `PNG`, Linux GTK clipboard, both from pixels decoded at most 4096 px a side from a file of at most 64 MiB; Android a `content://` URI), Save a copy on Windows and Linux (on Linux the GTK save and open dialogs, which also serve backups, exports, imports, and file pickers), Open in default app on Windows (`ShellExecuteW` `open`), Linux (`desktop_helpers::open_file`, `xdg-open`), and Android (a chooser with a one-file read grant), never for an executable, script, shortcut, or network path, and Open folder on desktop. Android hands files out only through the `FileProvider` folders in `res/xml/shared_paths.xml` (chat files and the paste cache). Tests: `catalog_fill_and_media_viewer_test.dart` (Copy picture pixels, two-slash paths refused), `sent_attachments_test.dart`, `desktop_helpers::tests::only_a_plain_local_file_is_handed_to_the_default_app`.
- Per-chat budget, 4 trust presets & MCP import: Settings > Safety & Budget provides 4 trust presets (`Off` / `Strict` / `Balanced` / `Sandbox`) and an optional per-chat spending limit override; Settings > Agent, Tools & Sleep provides per-tool `Ask / Allow / Off` permissions, native multi-folder picker + Git branch badge, Add server + safe `Import MCP JSON` (`enabled: false`, Android command stripping), and Background & Sleep Survival controls ("Keep replies going after you close the window" only while the desktop daemon is in use, the battery stay-awake switch only on Windows); `ToolTimelineView` breaks compound shell commands into readable numbered steps (display-only; permits always bind raw arguments).
- Low-memory mode: `detectLowMemoryHost()` (`apps/bistre_app/lib/platform/host_memory.dart`; Windows `GlobalMemoryStatusEx`, Linux `/proc/meminfo`, Android `ActivityManager.isLowRamDevice`) sets `BistreThemeData.reducedEffects` (no shadows) and a 33 ms (30 fps) leaf redraw interval; probing never blocks startup.
- Linux desktop: notifications use `notify-send` with the desktop's message sound when asked; focus comes from the app lifecycle; run-at-startup writes `~/.config/autostart/bistre.desktop` (`$XDG_CONFIG_HOME` honoured) with the app path quoted per the Desktop Entry spec.
- Window caption: `<chat title> - Bistre`, `Replying · <chat title> - Bistre`, or `Settings - Bistre` via the runner's `setWindowTitle` channel.
- Accessibility: modal/drawer overlays wrap the occluded shell in `ExcludeSemantics`; disabled `EngravedButton`s keep an outline and muted ink; focus rings appear only in keyboard highlight mode; `readableInk` nudges secondary/muted/accent/status inks to ≥ 4.5:1 on all four surfaces.
- Split diff: tool diffs render unified; when the timeline is at least `kSplitDiffMinWidth` (720 px) wide after dividing by the text scale, a `Split` / `Unified` toggle shows old | new columns. `pairSplitDiffRows` aligns each run of removals with the additions that follow; context lines appear on both sides and headers span both; diffs are always LTR.
- Unavailable cost: `NodeUsageMeta.costKnown` reads the node's `cost_known`. An unpriced reply shows no price, only a quiet `BistreUiIcon.info` button (`apps/bistre_app/lib/features/chat/cost_unavailable_button.dart`) whose popover explains that the reply counts as `$0` toward the daily limit and lists the model and token counts (Spec 06). Tests: `apps/bistre_app/test/diff_and_cost_test.dart`.

- Runs per chat (`folio_controller_runs.dart`): any number of chats may reply at once. Live state is a map from chat to its streaming node, never one "streaming chat": each chat keeps its own Stop, live text (a chat opened mid-reply shows its text so far), tool rows and approvals. An approval asked in a background chat waits in that chat. The sidebar marks a chat with a 7 px labelled dot: replying (brass), waiting for you (warn), new reply (wax: finished while another chat was open, cleared when opened), stopped with a problem (error). Tool rows belong to their chat and run: a new run starts with none from earlier runs, at most 200 rows per chat, output capped at 16 KiB (the full output stays in history). ## 5. Interface Rules (design §1.2)
Checked by `ui_craft_test.dart`, `composer_toolbar_test.dart`, `context_breakdown_test.dart`, `display_prefs_test.dart`, `anti_pattern_regression_test.dart`, and `ux_wave2_parity_test.dart`.
- Layout: the shell header spans the chat and its side panes; settings rows are measured (`LabelControlLayout`); popovers stay inside the window; icons scale with text; table cards are as wide as their table; the feed stays at the bottom when a notice or the composer shortens it; a bubble holds only the message.
- State on the control: a slider that follows a default is `unset`; the context ring and popover share one rounding (`contextPercent`) and the ring is full and red on a reported overflow; an active filter shows its query; Save shows unsaved changes; rewrite tools name their scope.
- Copy: internal codes are shown in words (run status, lore reasons, prompt parts, tool permissions, schedules); a label never repeats its button, value, placeholder, or heading; an approval names the tool and its target (`approvalSummary`); a new chat is titled in the current language.
- Placement: bulk deletion lives in Settings → Storage; each panel opens from one place; keyboard hints are hidden on touch devices; each state shows once.
