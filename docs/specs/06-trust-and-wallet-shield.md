# Spec 06 — Dual Trust Shield & Wallet Shield

## 1. Risk Tiers 0–3
Every tool invocation and side-effecting action is classified statically + dynamically before execution:
- **Tier 0 (Read-Only Auto-Run)**: `read`, `grep`, `glob`, `diff`, local FTS5 search, read-only MCP tools. Executes automatically in all presets.
- **Tier 1 (Reversible Workspace Edits)**: Hash-anchored workspace file edits inside capability-scoped workspace `Dir`. Captures pre-image snapshot before write, enabling instant 1-tap rewind.
- **Tier 2 (External / Destructive / Paid Actions — Inline Wax Seal Approval)**: Shell commands, git mutations, external network/MCP writes, paid image/video generation. Requires explicit inline Wax Seal user confirmation showing exact target, command, and estimated cost.
- **Tier 3 (Hard Secret / Exfiltration Block)**: Attempts to read or transmit OS secret vault files, `.env` credentials, private keys, or symlink escapes outside workspace root are unconditionally blocked with `DiagnosticKey::ToolEditHashMismatch` / security audit log.

## 2. Mode Presets
- **Strict (Default-Safe)**: Tier 0 auto; Tiers 1–2 require explicit approval; Tier 3 hard-blocked.
- **Guided**: Tiers 0–1 auto (with 1-tap rewind); Tier 2 requires explicit approval; Tier 3 hard-blocked.
- **Sandbox**: Tiers 0–2 auto inside isolated worktree/container boundary ONLY; Tier 3 and Wallet Shield hard ceilings remain active.
- **Unknown presets and imports**: an unknown preset name parses to `Strict`, never a looser one. A settings import accepts only known fields and is refused with `diag.import.loosens_safety` when it would loosen safety (a more permissive preset, or a higher or removed daily limit); the toast's **Import anyway** re-imports with the user's confirmation. Every import revokes outstanding tool permits (`broker.invalidate()`). Test: `storage_files::tests::settings_import_never_loosens_safety_without_confirmation`, `apps/bistre_app/test/settings_import_test.dart`.
- **Approval card** (every preset): Approve once · Approve for chat (this exact call again in this chat; any arguments only for Tier-0 reads) · Deny (the identical call is refused for the rest of the run without asking) · Stop run (refuse and cancel the run). An approval never times out into a decision; the run waits, badged, with keep-awake released (Spec 04 "Live approvals in a run").

## 3. Wallet Shield (Unconditionally Overrides Self-Healing)
- All costs, reserves, and spend limits use exact `MoneyMicros(i64)` (`1 USD = 1_000_000`) persisted in `wallet_ledger` alongside real input/output token counts.
- **Unlimited or Custom Daily Spending Limit**: `AppSettings.wallet_daily_ceiling_micros` is `Option<MoneyMicros>`. Setting `None` enables **Unlimited spending** (zero artificial ceiling for heavy users or local/flat-rate plans); setting any positive `MoneyMicros` enforces a hard UTC-day spend check (`sum_wallet_spend_since_micros`) before every metered cloud request, blocking execution with `DiagnosticKey::WalletCeilingExceeded` once reached (loopback local providers such as Ollama/vLLM always cost `$0.00` and bypass cloud caps). "Loopback" is decided only by `bistre_core::net::is_loopback_url`, which parses the URL and accepts `http(s)` hosts `localhost` or a loopback IP; prefix tricks such as `http://localhost.evil.com` stay metered (shared with MCP).
- **Spend reservations (fail closed)**: before every paid request the run reserves an input-cost estimate in `wallet_ledger` (`status = reserved`) inside one writer transaction (`StorageHandle::reserve_wallet_spend_with_chat_cap`) that refuses the request when today's settled + reserved spend already meets the daily ceiling **or adding the estimate would pass it** (checked addition; a negative estimate is never a reservation), and, for a chat with a cap (`kv_meta["thread_spend_limit:<id>"]`), when the chat's whole ledger spend plus the estimate would pass the cap (`diag.wallet.ceiling_exceeded`, detail `thread_spend_limit`). Concurrent runs and sub-agents serialize and cannot overshoot together. `bistre_core::wallet::SpendReservation` is the only way to reserve; it settles to the exact cost on commit and releases on drop (failure, cancel before output, retry). Engine start releases orphaned reservations. A settings or ledger read failure, or a chat cap that is not a whole non-negative number of micro-USD, denies the request with `diag.wallet.check_unavailable` (an empty value means no cap). Tests: `crates/bistre-core/src/wallet.rs`, `wallet_flow_tests.rs`, `bistre-storage` `a_reservation_that_would_exceed_the_ceiling_is_refused` / `a_chat_cap_counts_the_chats_ledger_spend_and_the_estimate`.
- **Unknown prices (fail closed)**: while a daily ceiling or chat cap is active, a request whose model has no registry price is not sent (`diag.wallet.price_unknown`); the inline notice offers **Allow once**, which lets that chat's next run through (`allow_unpriced_once`, cleared when the run ends). Read aloud and live voice pass the same gate (`allow_unpriced_media_once`); read aloud then falls back to the free OS voice.
- **Billed usage**: Gemini thinking tokens (`thoughtsTokenCount`, Interactions `total_thought_tokens`) are billed as output on top of the answer; `OpenAI` reasoning and Anthropic thinking are already inside `output_tokens`. Anthropic cache writes are split by TTL (`usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`) and billed at the registry's 5-minute / 1-hour write rates; an unknown write rate makes the cost unknown, and an unknown read rate bills reads at the full input rate (an upper bound). A sent request whose stream carried no usage (stopped before the final usage frame, or a provider without stream usage) is billed from the reserved input estimate plus the output counted locally, never `$0`, and raises `diag.wallet.usage_estimated` (`wallet::billable_usage`).
- **Read aloud and live voice**: both reserve through the Wallet Shield (`engine_extras::reserve_media_spend`): a reached daily cap blocks them before any request; read aloud settles its input estimate (speech endpoints return no usage). Per-turn live-voice metering needs audio-token prices the registry does not carry yet; until then a live session is gated at start only (`TASKS.md` open item).
- **Paid Media Gate & Retry Ceiling**: Paid media jobs require explicit Wax Seal confirmation above configurable threshold and cap automatic retries to `0` on indeterminate transport drops (`INDETERMINATE_HALT`).
- **$0 Local Priority**: Automatically ranks local Ollama/llama.cpp/ComfyUI models ahead of metered cloud models when slot-compatible.

## 4. Untrusted Imports & OS Hand-Off
- **`import_policy::with_imported_permissions`** runs on every imported character card (`.png`, `.json`, `.charx`): local filesystem, shell, web, and MCP grants in `extensions` are removed, MCP `command`/`args` are dropped, Windows UNC paths (`\\server\share`, `//server/share`, `\\?\UNC\…`) are cleared from every field, and media paths must be relative `media/<name>`.
- **OS open**: `process_util::is_blocked_open_path` / `validate_web_link` (25 blocked executable/script/shortcut extensions, UNC refusal, `http(s)` links only); the desktop `openFolder` bridge (`apps/bistre_app/lib/platform/desktop_host.dart` + `apps/bistre_app/windows/runner/flutter_window.cpp`) opens only existing local directories with the `explore` verb.
- **Pricing for the spending limit** comes only from the live registry (Spec 03); an unpriced reply counts as `$0` toward the limit (lower bound) and is marked `cost_known: false`; the chat shows a quiet info button with a breakdown popup instead of a price (Spec 08 §3).
