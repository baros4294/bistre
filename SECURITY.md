# Security Policy

## Privacy & Telemetry Guarantee
Bistre collects **zero telemetry, zero analytics, and zero crash-report uploads**. All conversations, drafts, search indexes, and credentials stay local to the user's device or explicitly QR-paired execution node.

## Security Architecture
- **Credentials**: Stored only on the execution node, never in SQLite, never across Remote Bridge, never in logs, and always encrypted at rest. **Windows**: DPAPI (`CurrentUser`) entries in `bistre_vault.dpapi.json`. **Android**: entries sealed with XChaCha20-Poly1305 under a random data key that a non-exportable Android Keystore AES-256-GCM key (StrongBox when available) wraps; only the wrapped key is stored, in `noBackupFilesDir`. **Linux**: the same sealing, with the data key held by the Secret Service (`oo7`: D-Bus or the Flatpak portal) or derived with Argon2id from `BISTRE_VAULT_PASSPHRASE` on headless hosts. Each sealed entry binds its name as associated data. Without any key source the Linux vault refuses to store new keys (older plaintext entries stay readable until a key source appears, then are encrypted in place). If the key changes, the unreadable vault is set aside (`*.key-mismatch-<ms>`) rather than deleted.
- **Transport**: Pure Rust TLS (`rustls` + `rustls-platform-verifier`) honoring OS/enterprise CA trust stores; `openssl-sys` is banned via `deny.toml`. Remote Bridge uses TLS 1.3 mTLS with QR-exchanged certificate fingerprint pinning.
- **Tools & Filesystem**: Workspace edits require `cap-std` capability-scoped handles (`O_NOFOLLOW`) and `blake3` line-range hash anchors. Every child process is created through `process_util::no_window_command` (Windows `CREATE_NO_WINDOW`, Unix process group, scrubbed provider keys) and its whole tree is killed on timeout. Each Windows child joins its own `KILL_ON_JOB_CLOSE` Job Object and Linux/Android children receive `PR_SET_PDEATHSIG(SIGKILL)` (audited shim in `bistre_crypto::containment`, Spec 04 / ADR-0010), so children never outlive a crashed Bistre.
- **Network Egress for Model-Directed Traffic**: `web_fetch`, remote MCP servers, and pricing-catalog GETs use `PublicWebTransport` (public-IP pinning at connect time, no proxy, re-validated redirects, IANA special-purpose IPv4/IPv6 exclusions, streamed body caps). Loopback MCP servers use a separate no-redirect client; private LAN hosts are refused. Pricing-catalog GETs (OpenRouter, Vercel AI Gateway, LiteLLM, models.dev) send no identifiers and run only while a non-local provider is streaming.
- **Credentials Hygiene**: Pasted API keys and custom header values are stripped of line breaks, zero-width characters, the BOM, and control characters; several keys per provider rotate round-robin; keys travel only in headers, never in request URLs or logs.
- **Untrusted Imports**: Imported character cards pass `with_imported_permissions` (capability grants, MCP commands, and Windows UNC network paths removed; media restricted to `media/<name>`). The desktop open-folder bridge opens only existing local directories and refuses executables, shortcuts, and UNC shares.
- **Tool Approvals**: Every executed tool call claims a one-use permit bound to its exact arguments; any settings change revokes outstanding permits synchronously.
- **OTA Supply Chain**: Every Track-A data pack and Track-B release manifest is verified offline with `minisign-verify` (Ed25519) before staging; payloads require a SHA-256 digest, HTTPS, and a `256 MiB` streamed cap; releases carry GitHub Sigstore build provenance attestations. Android publishes a single direct GitHub `arm64-v8a` APK with `PackageInstaller` verification and pinned APK signing-certificate SHA-256 checks.

## Reporting a Vulnerability
Please report security issues privately via GitHub Security Advisories on this repository rather than opening a public issue. Include reproduction steps, affected platform/version, and impact assessment.
